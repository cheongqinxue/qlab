Transformers — efficiency

Cost model — prefill vs decode
Where time and memory go

Attention is $\mathcal{O}(n^2)$ in sequence length $n$ for prefill (process the prompt in one or few passes). Each query token compares to every key; GPUs often become compute-bound on large matmuls here.

Decode (one new token per step) reuses past keys and values via a KV cache. Work per step is $\mathcal{O}(n)$, but you must read the whole cache from memory each time — often memory-bandwidth-bound. That is why KV compression (GQA, MLA) matters more at inference than in training.

SDPA math: core sheet (MHA + per-head SDPA).

Decode: cache grows each step

Rough KV size per layer: $2 \times n_{\mathrm{kv\_heads}} \times d_k \times \text{seq\_len}$ (K and V), times number of layers and batch.

Head layouts — MHA, GQA, MQA
Same SDPA inside each head; different K,V sharing

MHA (multi-head attention): every query head has its own key and value projections. Maximum flexibility; largest cache. MQA (multi-query): all query heads share one K and one V. Smallest cache; can hurt quality. GQA (grouped-query): $g$ KV groups; each group feeds $h/g$ query heads — usual LLM compromise.

Queries stay multi-head; only the number of distinct K/V streams stored in the cache changes.

MHA — reference point
  • $h$ heads each: $\mathrm{head}_i=\mathrm{SDPA}(XW_i^Q,XW_i^K,XW_i^V)$ then $\mathrm{Concat}(W^O)$
  • Used in GPT-2, BERT, ViT; still common in encoders and smaller models
  • When batch decode at long context, KV RAM can exceed weights
Picking GQA group size
  • Start from target $n_{\mathrm{kv\_heads}}$ allowed by hardware (e.g. 8 on 32 Q heads → GQA-4)
  • Validate perplexity / downstream tasks vs full MHA before shipping
  • Some checkpoints publish “GQA-8” in config — map to num_key_value_heads
MLA — compress what you cache
Multi-head latent attention (DeepSeek-class)

Instead of storing full per-head K and V tensors, MLA projects the hidden state into a low-rank latent $c^{KV}$ per token and caches that. Before SDPA, latents are up-projected to head-specific K and V (or equivalent via weight absorption at decode so full K never materializes).

A decoupled RoPE path keeps positional information on a small slice of q/k so compression does not erase order.

Goal: fewer bytes moved per decode step while keeping softmax attention semantics (often with higher arithmetic intensity than MQA).

FlashAttention — exact, IO-aware SDPA
Problem with naive attention

Materializing the full $n \times n$ attention matrix in GPU HBM (high bandwidth memory) forces many read/write round trips. SRAM on-chip is tiny but fast — classic attention underuses compute because it is waiting on memory.

Tiling idea
  • Exact — same numerics as naive SDPA (unlike many sparse approximations)
  • FlashAttention-2/3: better warp scheduling; FP8 paths on supported GPUs
  • MLA/sparse stacks often ship custom kernels (e.g. FlashMLA) with the same IO mindset
PyTorch SDPA dispatch

torch.nn.functional.scaled_dot_product_attention picks a backend when allowed: FlashAttention, memory-efficient, or math fallback. Enable with sdpa kernel flags / PyTorch 2.x defaults; dtype and head dim must match kernel constraints.

Flash speeds prefill and training; it does not replace GQA/MLA for decode KV size.

Sparse patterns — fewer pairs
Sliding window

Each query attends only to the last $w$ tokens (plus optional globals). Complexity $\approx \mathcal{O}(n \cdot w)$. Mistral-class models stack layers with shifted windows to widen receptive field.

NSA / DSA (hierarchical sparse)

NSA (Native Sparse Attention): trainable mix of (1) compressed token blocks, (2) selected important tokens, (3) local window — hardware-aligned block sparsity. DSA (DeepSeek Sparse Attention): token-level sparse patterns with fused decode kernels. Still softmax on chosen keys; less work than dense $n^2$.

Mixture of experts (MoE)
Params vs FLOPs per token

A MoE model can have many more parameters than a dense model of the same width, but each token only runs k of N expert FFNs. Active FLOPs scale like a smaller dense FFN × k (plus router + attention unchanged).

Catch: all experts still occupy GPU memory at inference unless offloaded or sharded. MoE saves compute per token, not automatically VRAM for weights.

Expert parallelism (training & serving)

Experts are often sharded across GPUs (expert parallel, EP). A token’s router picks experts; activations are sent to the devices holding those experts (all-to-all communication). Attention/tensor parallel stacks on top of this.

Load balancing
  • Routers collapse to few experts → wasted capacity; add auxiliary load-balancing loss (Switch Transformer)
  • Capacity factor — drop overflow tokens when an expert’s buffer fills (train instability if too aggressive)
  • Shared expert — always-on FFN + routed experts (Mixtral-style) stabilizes quality
  • Monitor per-expert utilization dashboards in training
Inference notes
  • Latency includes router + dispatch; small k helps (e.g. 2 experts/token)
  • Batching: tokens in a batch may hit different experts → harder to keep GPUs full
  • Quantization (GPTQ/FP8) applies per expert; EP serving matches training shard layout when possible — see compression
  • Not a KV-cache trick — pair MoE with GQA/MLA for long-context decode
Scoring & alternatives
DiffAttention

Split Q/K into two groups; compute two softmax attention maps; subtract them so shared “background” mass cancels (noise-canceling analogy). Changes the score matrix, not KV sharing. ICLR 2025 Diff Transformer; each branch can use flash SDPA.

Linear & state-space layers
  • Linear attention — feature map $\phi$ so $(\phi(Q)\phi(K)^\top)V$ avoids explicit $n \times n$
  • Mamba / SSM — fixed-size state updated per token; $\mathcal{O}(n)$ recurrence
  • Hybrids — alternate full-attn layers with SSM/linear layers in one model
  • Different inductive bias — not drop-in for every MHA layer
Training throughput
  • bf16/fp16, gradient checkpointing (recompute vs RAM), sequence packing (reduce padding waste)
  • Tensor parallel (shard weights), pipeline parallel (shard layers), context parallel (shard long seq)
  • Parameter updates without full fine-tune: PEFT sheet
Quick chooser
  • Long prompt, one shot — FlashAttention / FlexAttention; dense or NSA prefill
  • Long chat decode — GQA or MLA; quantize KV (FP8/FP4) where supported
  • Ultra-long context — window + sparse (NSA) or hybrid SSM
  • Quality ceiling — MHA or large GQA groups; ablate before cut
  • More capacity, same FFN budget — MoE layer (watch balance + EP)
