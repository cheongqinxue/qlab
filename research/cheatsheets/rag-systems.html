RAG systems

End-to-end pipeline

Offline: ingest once (or on schedule). Online: each user question retrieves fresh context, then one LLM call (or agent loop).

Ingestion
  • Sources: PDF, HTML, wiki, tickets, DB exports — normalize to text
  • Parse tables/headers; keep source URI and version for citations
  • Respect access control — index tenant/user ACL in metadata (security)
Chunking

Split documents into pieces that fit the context window and embed model limits. Too small loses context; too large dilutes the vector. Overlap (e.g. 10–20%) reduces boundary cuts mid-sentence.

  • Fixed token windows — simple default
  • Structure-aware — by heading, paragraph, page
  • Parent–child — retrieve small, inject larger parent for LLM
Prompting the LLM
  • System: answer only from provided context; say “I don’t know” if missing
  • Inject retrieved chunks with labels/source ids for citations
  • Keep total tokens under model limit — trim k or summarize chunks
Query-side tricks
  • HyDE — LLM drafts a hypothetical answer; embed that for search (can help vague queries)
  • Query rewrite — LLM expands acronyms or sub-queries
  • Multi-query — several retrievals merged (RRF fusion)
Evaluation (what to measure)
  • Retrieval — recall@k on a labeled set (see retrieval sheet)
  • Faithfulness / groundedness — are claims supported by retrieved text?
  • Answer correctness — human or LLM-as-judge vs gold answer
  • Citation accuracy — does the cited chunk actually contain the claim?
Production ops
  • Re-embed on model change — vectors are not portable across unrelated embedders
  • Incremental index updates vs full rebuild
  • Log query + chunk ids; redact PII in logs
  • Rate limits and cache frequent queries cautiously (stale answers)
RAG vs fine-tune vs long context
  • RAG — fresh facts from your docs; cite sources; index updates without retraining
  • Fine-tune — style, format, domain language; not a substitute for live KB
  • Long context — dump whole doc if it fits; still pay tokens; retrieval scales cheaper for huge corpora
Common failures
  • Empty retrieval → LLM fills gaps confidently
  • Duplicate/near-duplicate chunks waste context
  • Conflicting chunks — no policy to reconcile
  • Prompt injection in indexed user content
Minimal stack (starting point)
  • Embed: open or hosted embedding API
  • Store: Postgres pgvector or managed vector DB
  • App: retrieve top‑k → optional rerank → LLM API with context block
  • AuthZ on metadata filters per request
