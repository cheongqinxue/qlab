ANN retrieval & indexes

Exact k-NN vs ANN

k-nearest neighbors (k-NN) compares the query to every vector — correct but $\mathcal{O}(N)$ per query. Approximate nearest neighbor (ANN) trades a small amount of recall for much lower latency and RAM at millions–billions of vectors.

Graph — HNSW
HNSW (hierarchical navigable small world)

Build a multi-layer proximity graph: upper layers for long jumps, bottom layer for fine search. Query greedy-walks from an entry point. Default in many libraries (Faiss, hnswlib, Qdrant, pgvector option).

  • M — max neighbors per node (accuracy vs memory)
  • efConstruction — build-time search width (index quality)
  • efSearch — query-time width (↑ recall, ↑ latency)

Each dot is one stored embedding. Upper layers skip across the space; bottom layer finds the actual nearest neighbors.

Cluster — IVF
IVF (inverted file index)

Train k-means on vectors → nlist clusters. Each vector assigned to a cluster (inverted list). At query: find nearest centroids (nprobe clusters), search only those lists — sublinear when nprobe ≪ nlist.

IVF + PQ (Faiss classic)

IVF-PQ — cluster with IVF, then store each vector compactly with product quantization (PQ) inside lists. Very memory-efficient; tune nprobe and PQ params for recall.

Compression
PQ (product quantization)

Split $D$-dim vector into $m$ subvectors; each subvector quantized to one of $k$ centroids (codebook per segment). Store $m$ small codes instead of $D$ floats — asymmetric distance computation (ADC) at query time.

SQ (scalar quantization)

Scalar quantization — per dimension (or block), map float32 → int8 (or binary). Simpler than PQ; common for int8 indexes (pgvector, some GPU paths). Often ~4× smaller with small recall loss if calibrated.

Other compressions
  • Binary / Hamming — extreme compression; recall hit on fine semantic tasks
  • OPQ — optimized rotation before PQ (Faiss)
  • Residual PQ — ColBERTv2-style on token stores
Other ANN families (beyond HNSW / IVF)
ScaNN (Google scalable nearest neighbors)

Combines coarse partitioning (similar spirit to IVF) with learned or optimized anisotropic vector quantization (AQ) — quantization that respects which directions matter for distance, not just uniform bins. Often strong recall/latency on CPU; shipped in Google Vertex Matching Engine and the open ScaNN library.

Think: cluster → compress vectors aggressively → asymmetric distance at query time. Tuned as a bundle; less DIY than raw Faiss knobs.

DiskANN (disk-resident graph)

Builds a Vamana graph (related to NSW/HNSW family) but stores it on SSD with careful IO scheduling so billion-point search works when RAM cannot hold the full graph. Query latency higher than in-RAM HNSW but footprint much smaller per point.

Use when: corpus too large for RAM, still need graph-quality ANN, can tolerate ms–tens of ms disk IO.

CAGRA (NVIDIA cuVS)

CAGRA — GPU-built and GPU-searched graph ANN (successor line to RAFT/cuML neighbors). Targets batch and high-QPS search where GPU memory holds the index; very fast when data fits VRAM.

Pair with GPU embedding pipelines; less common in tiny Postgres sidecars.

Annoy (approximate nearest neighbors oh yeah)

Spotify’s Annoy: random hyperplane trees — binary splits on random directions, forests of trees, majority vote on candidates. Simple, mmap-friendly, static indexes. High-dimensional semantic vectors often prefer HNSW, but Annoy remains easy for moderate dimension and frozen corpora.

NSG / navigable small-world variants

NSG (navigating spreading-out graph) and relatives build a sparse graph with monotonic greedy search guarantees similar to HNSW. Faiss and research code expose NSG; some teams compare NSG vs HNSW on build time and recall — not a separate product category, but an alternative graph construction.

LSH (locality-sensitive hashing)

Hash similar vectors into same buckets with probability related to distance. Classic for very high-D sparse text; for dense neural embeddings, graph (HNSW) or IVF+PQ usually wins on recall. Still seen in hybrid systems and teaching; SimHash for near-duplicate detection.

FLAT / exact k-NN (brute force)

Faiss IndexFlatL2 / IndexFlatIP: compare query to every vector — exact, simple baseline. Feasible up to ~low millions on GPU or small dims; use to measure ANN recall and for tiny collections where index overhead isn’t worth it.

Tree indexes in high dimensions

KD-trees and vanilla ball trees degrade when dimension is hundreds+ (curse of dimensionality). Random-projection forests (Annoy) and graphs (HNSW) cope better with dense embeddings. Don’t assume “tree = fast” for modern embedding dim (768, 1536, …).

When to pick which family
  • Default RAG corpus in RAM — HNSW (pgvector, Qdrant, Milvus, Faiss HNSW)
  • Huge N, tight RAM — IVF-PQ or ScaNN-style AQ; or DiskANN if graph quality on SSD
  • GPU-heavy stack — Faiss GPU flat or CAGRA; batch queries
  • Static snapshot, simple ops — Annoy mmap index
  • Prove ANN quality — exact flat on sample + recall@k sweep on efSearch / nprobe
HNSW vs IVF (rule of thumb)
  • HNSW — great default latency/recall up to large RAM-bound corpora; painful to rebuild huge indexes
  • IVF — scales with training; good with PQ for RAM; needs nprobe tuning per dataset
  • Many engines expose both or hybrid (pre-filter metadata + HNSW)

Tuning & gotchas
  • Measure recall@k vs exact search on a held-out query set — ANN params are not portable across corpora
  • Re-embed → full rebuild unless engine supports online reindex
  • Normalize vectors if metric assumes cosine; Faiss inner product on normalized = cosine
  • Metadata pre-filter: confirm “filter + ANN” is integrated (not filter-after-ANN on small sets only)
  • PQ/SQ: store original or higher-precision rerank pass for top candidates if quality drops
