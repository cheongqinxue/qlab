MLOps — lifecycle

What MLOps is (here)

MLOps is how you turn a one-off training run into something you can repeat, promote, deploy, and watch without heroics. It is not the same as learning rate schedules (training loop) or picking a GPU (cloud DL). Those sheets build the model; DevOps builds the platform (containers, CI/CD, infra, logs); MLOps adds model-specific registry, drift, and lineage.

Lifecycle stages
  1. Define — problem, success metric, constraints (latency, cost, compliance).
  2. Data — ingest, version, split; see data for training.
  3. Train & evaluate — experiments, gates on metrics; debug with troubleshooting.
  4. Register — immutable artifact + metadata (registry).
  5. Deploy — serve behind an API; runtime detail in serving.
  6. Monitor — quality, drift, cost (monitoring).
  7. Retire or retrain — triggered by drift, policy, or new data.
Environments
Dev / staging / prod

Dev is where notebooks and fast experiments live; configs may be messy. Staging runs the same container and pipeline as prod on holdout data or shadow traffic. Prod serves real users; only promoted artifacts land here. Skipping staging works until it does not — treat promotion as a deliberate gate, not a file copy.

What counts as a “version”

A model version is not only weights: it is weights + code + dependencies + data snapshot (or index id) + eval report. For RAG, version the embedding model, chunking policy, and vector index build id together with the LLM checkpoint. For LoRA, version base model id plus adapter weights (PEFT).

LLM & agent products

LLM products often ship a stack: base model, optional fine-tune, system prompt template, tools, RAG index, and safety filters. MLOps tracks each layer that can change behavior independently, so rollback means “revert index v3 and prompt v2,” not only “old checkpoint.” Agent loops add tool schemas and policy configs — see control patterns and reliability.

Chooser — which MLOps page next

Automating train → eval → register → pipelines. Shipping and staging models → registry & promotion. Live quality and drift → monitoring. Audit, access, lineage → governance.
