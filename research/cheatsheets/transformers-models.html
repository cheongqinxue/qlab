Transformers — seminal & recent models

How to read this page

Benchmarks move every month; this sheet tracks ideas that changed the default stack or attack a real pain point — context, decode cost, reasoning, multimodal glue, persistent memory, non-AR generation (diffusion LMs, NCM), end-to-end memory banks, looped depth, decision-only models (Jev), and sub‑3B deploy. For attention math and blocks, see core; for KV cache, MoE serving, and kernels, see efficiency.

(a) Seminal models — mechanism & why they stuck
Foundations (2017–2020)
Model How it works (one line) Why significant
Transformer (2017) Encoder–decoder stacks of multi-head self-attention + FFN; no recurrence. Made long-range dependencies parallel to train; template for almost everything after.
BERT (2018) Encoder-only; masked language modeling (MLM) sees bidirectional context. “Pre-train then fine-tune” for NLP; strong embeddings and classifiers; not a chat model.
GPT-2 / GPT-3 (2019–20) Decoder-only causal LM — predict next token on web-scale text. Scale → few-shot in-context learning without weight updates; path to assistants.
T5 (2020) Encoder–decoder; every task framed as text-to-text with task prefixes. Unified recipe for summarization, QA, translation; influenced instruction formatting.
Vision Transformer (ViT) (2020) Image patches as tokens + transformer encoder. Showed CNNs were not mandatory at scale; link to vision sheet.
CLIP (2021) Dual encoders trained with contrastive image–text pairs. Shared embedding space → zero-shot classification and retrieval; RAG over images.

Model / result Mechanism Why significant

Three families (still the map)
  • Encoder-only — embed, classify, bi-encoder retrieval (BERT, modern E5/BGE class)
  • Decoder-only — chat, code, agents, most “LLM” products (GPT, LLaMA, Qwen, …)
  • Encoder–decoder — seq2seq, speech, some translation (T5, Whisper)

What “seminal” does not mean
  • Not “best on MMLU today” — many seminal papers are obsolete as products.
  • Not every SOTA checkpoint — only designs that rewired engineering defaults.
  • Leaderboards reward breadth; production often rewards cost, latency, and reliability on your task.
(b) Recent directions — bottlenecks & promised fixes
Pain point map

Below: problem → idea → examples. Dates are approximate; vendors ship overlapping features. Prefer tracing the mechanism over memorizing model names.

KV cache & decode memory

Bottleneck: autoregressive decode reads growing key/value tensors every step — bandwidth-bound on long chats.

  • GQA / MQA — share keys/values across heads (LLaMA 2+ class); fewer bytes per token in cache.
  • MLA (multi-head latent attention) — compress KV into a low-rank latent (DeepSeek-V2/V3 class); strong cache savings.
  • Quantized KV — FP8/INT cache (inference stack, not a single paper model).

Efficiency sheet — GQA, MLA.

Long context & prefill cost

Bottleneck: attention grows with context; huge prompts are slow and RAM-heavy at prefill.

  • RoPE scaling (YaRN, PI, …) — extend positions without full retrain from scratch.
  • Sliding / local windows — each layer sees a band (Mistral early layers + SWA pattern); linear-ish memory for very long streams.
  • Ring / sequence parallel — split context across devices (systems idea paired with long-context models).
  • SSM hybrids — sub-quadratic recurrence mixed with attention layers (Jamba-class).
Training & inference FLOPs

Bottleneck: dense transformers activate full FFN on every token; training clusters are expensive.

  • MoE (mixture of experts) — router activates top‑k FFN experts per token; more params, fewer active FLOPs (Switch, Mixtral, DeepSeek-MoE/V3).
  • Chinchilla-style data scaling — mid-size models on more tokens (Phi, many open “3B–8B” strong baselines).
  • Distillation — teacher LM labels for smaller deployable students (not novel arch, but default cost lever).

Core — MoE block · MoE serving.

Sub-quadratic sequence models

Bottleneck: pure self-attention is $\mathcal{O}(n^2)$ in sequence length for prefill.

  • Mamba / Mamba-2 (SSM) — selective state-space layers; linear-time recurrence with gating.
  • Jamba and hybrids — alternate SSM blocks with standard attention layers for recall + speed.
  • Structured sparse attention — block-sparse, native sparse patterns in some research/industrial stacks.

Trade-off: long-range copy and exact recall vs attention; hybrid stacks are the pragmatic middle.

Reasoning & tool use

Bottleneck: next-token LM loss does not guarantee multi-step math, planning, or verifiable chains.

  • Chain-of-thought (CoT) — elicit intermediate steps at inference (prompting + scale).
  • Process / outcome supervision — train on step labels or verifiable rewards (math, code tests).
  • RLVR / RL on verifiable rewards — DeepSeek-R1 class: reinforcement when answers are checkable.
  • Test-time compute — more inference steps (search, self-consistency, o-series style); buys accuracy for latency/cost.

Mostly training and inference recipes on top of decoder stacks — not a replacement for attention.

Multimodal friction

Bottleneck: bolt-on vision encoders + projection adapters lag behind native text quality and add latency.

  • LLaVA-style — frozen ViT + lightweight connector into LM; fast to ship, ceiling limited.
  • Native interleaved tokens — image/video patches in the same transformer as text (Gemini, Qwen2-VL, LLaMA 3.2 vision class).
  • Unified speech — audio tokens or encoders in one chat model (GPT-4o-style pipelines).

Vision · Audio.

Adaptation without full fine-tune

Bottleneck: full weight updates are slow, risky, and multi-tenant expensive.

  • LoRA / adapters / IA³ — low-rank or small modules on frozen base (production default).
  • Prompt tuning / soft prompts — learn continuous prefix vectors only.

Diffusion & non-AR text generation
Diffusion language models (DLMs)

Bottleneck: autoregressive (AR) decode is strictly serial — one token at a time — so long outputs mean many forward passes and a growing KV cache. Diffusion language models treat text as a sequence of masked or noised discrete tokens and refine the whole sequence over many steps, so many positions can update in parallel within a step (like image diffusion, but on token grids).

  • Mechanism — start from noise or masks; a transformer predicts cleaner tokens or denoising targets; repeat for $T$ steps (number of function evaluations, NFE).
  • Promise — parallel generation paths, potential alternatives to AR for throughput-sensitive workloads.
  • Pain today — quality often needs many steps; full-sequence updates each step are expensive; training and sampling recipes are less mature than AR + KV cache ecosystems.
  • Examples (research line) — Diffusion-LM, masked discrete diffusion (MDLM class), semi-autoregressive hybrids; compare to strong AR baselines on your task before betting production on NFE.

Image/video diffusion (latent space, DiT) is the same iterative denoising idea on pixels or latents — see image generation sheet. Text DLMs apply that loop to tokens, not patches.

NCM — Next-Concept Modeling

Bottleneck: DLMs still revisit the entire sequence each step; AR models revisit the entire history via KV cache. Both can waste work on fine details early in generation. Next-Concept Modeling (NCM) (Stanford/HazyResearch, 2026) is a coarse-to-fine alternative: learn a hierarchy of discrete codes, then generate one level at a time, with all positions within a level in parallel.

  • Stage 1 — multiscale residual VQ-VAE (vector-quantized variational autoencoder): text → $K$ levels of codes (short coarse → longer fine).
  • Stage 2 — transformer predicts level $1 \ldots K$ sequentially; inside each level, codes are parallel (like next-scale prediction in image models).
  • Why it matters — only $K$ sequential steps (often $K \ll$ token length); early levels are short → less compute per step; reported large speedups vs diffusion LM baselines at matched-ish quality on some benchmarks.
  • Caveat — two-stage training (tokenizer + generator); ecosystem is young vs AR; evaluate Gen-PPL / task metrics on your domain, not leaderboard alone.

Map: AR = serial tokens · DLM = parallel positions, many full-sequence steps · NCM = parallel within level, few hierarchical steps.

Internal memory banks (trained end-to-end)
What this means (vs other “memory”)

Here: extra parameters shaped as a memory bank — latent slots or vectors — that are randomly initialized and trained with the same LM objective as the transformer stack. Layers read the bank (usually cross-attention: token stream → queries, bank → keys/values) and gradients update bank contents like any other weights. That is different from KV cache (inference-only past tokens), RAG (external text index at query time), and from modules that mostly write memory only at test time without classic pretrain joint optimization.

Bottleneck addressed: capacity in FFN + attention weights is an implicit hash of facts; an explicit bank adds addressable, scalable storage without lengthening the context window linearly.

Core pattern
  • Bank — $M$ learnable memory tokens (or compressed latents), not tied to one document string.
  • Read — one or more layers cross-attend from the current hidden states into the bank (sparse or routed reads at scale).
  • Train — next-token (or denoising) loss backprops into bank + backbone together; no separate retrieval index build step.
  • Scale axis — increase $M$ or shard the bank (MoE-style routing) for more associative capacity at bounded read cost.
Representative lines (mechanism-first)
  • Mixture of Chapters — learnt sparse memory banks + chapter routing (MoE-like subsets of the bank per input); iso-FLOP gains on pretrain and instruction tuning; argues for memory as a scaling dimension and better phase-to-phase retention.
  • MemoryLLM — fixed-size memory pool in latent space inside the transformer; trained for self-update semantics (inject new text into the pool) while keeping earlier injections — blurs “weights vs writable state” but bank is part of the architecture.
  • Titans (persistent branch) — includes learnable, data-independent memory parameters (task prior) alongside short-window attention and a separate neural long-term module that updates at test time; read the paper for which parts are pure e2e pretrain vs test-time write.
  • Memorizing Transformers — external kNN over past keys plus learned integration (hybrid; influential on “attention + store”).
  • Transformer-XL / segment recurrence — cache hidden states across segments during training (context extension; precursor idea, not a large latent bank).
Design tensions
  • Read cost — dense cross-attention to $M$ slots is $\mathcal{O}(M)$ per layer; routing/sparsity (chapters, top‑k slots) needed at large $M$.
  • Interpretability — bank entries are latents, not human-readable chunks (unlike RAG citations).
  • Fresh facts after deploy — e2e banks freeze at checkpoint unless you continue training, add an updatable pool (MemoryLLM-style), or still use RAG for live docs.
  • Eval — probe knowledge retention, continued pretrain → SFT forgetting, and long-horizon needle tasks — not MMLU alone.

Product “memory” (MemGPT, tool notes, RAG) is orthogonal — orchestration around a frozen LM, not a jointly trained bank.

Looped transformers (weight-tied depth)
Idea

A standard stack uses different weights per layer — depth and parameter count grow together. A looped transformer reuses the same physical block(s) for multiple recurrence steps $r$, so logical depth $L_{\mathrm{eff}} \approx n_{\mathrm{prelude}} + r \cdot n_{\mathrm{recur}} + n_{\mathrm{coda}}$ while storing far fewer unique layers. Same bottleneck family as “more reasoning compute without a bigger checkpoint” — but via latent iteration, not necessarily longer chain-of-thought text.

Prelude · recurrent core · coda

Common 2025–26 recipe (Huginn, depth-recurrent LMs, iso-depth scaling papers):

  • Prelude $P$ — untied early layers embed tokens into a working latent space.
  • Recurrent core $R$ — tied weights applied $r$ times; maintains a latent state $\mathbf{s}_i$ updated each loop (input may be re-injected each step — design choice).
  • Coda $C$ — untied upper layers + LM head read out from final state.

Contrast Universal Transformer (2018): loop the same transition with optional adaptive halting (ACT) — early seminal form of tied depth. ALBERT ties weights across layers but does not usually expose “run 32 loops at test time” as a product knob.

Why loop — bottlenecks
  • Test-time compute (TTC) — increase $r$ at inference for harder tokens (latent “thinking”) without generating 10k CoT tokens.
  • Parameter efficiency — effective depth of 100+ block applications from a small physical stack (e.g. 8 real layers × many recurrences).
  • KV / context — some designs share cache across recurrences or keep reasoning in hidden state (model-dependent).
  • Adaptive compute — per-example or per-token loop count (train with random $r$, infer with larger $r$ when needed).
Design axes (not all loops are equal)

Controlled ablations (“looped models done right”) show gains depend on details, not only $r$:

  • Iteration envelope — where $P$, $R$, $C$ sit; full-stack recurrence (Ouro-style) vs sandwich recurrence (Huginn-style).
  • Input injection — whether each loop sees fresh token embeddings, a fixed prelude encoding, or only the evolving state.
  • Latent-state init — $\mathbf{s}_0$ from embeddings vs separate learned/init state; optional fast/slow state splits.
  • Training stability — tied depth aggregates gradients onto the same weights; DeepLoop adjusts residual scaling with loop count (visit-aware DeepNorm-style exponents).
  • Iso-depth scaling — one recurrence is not worth one untied layer; equivalence exponent ≈ 0.46 in recent scaling-law fits — tune $r$ with measurement, not analogy.

Hyperloop Transformers — loop-level hyper-connections between recurrent passes (stabilize signal across visits). MoE + looped cores appear in matched-parameter studies — sparse FFN and recurrence compose but must be co-designed.

Map vs neighbors
  • CoT / o-series token reasoning — extra compute in visible tokens; looped models spend compute in hidden recurrence (can combine both).
  • Mamba / SSM recurrence — linear-time state update along sequence; looped transformers recurrence along depth on a fixed chunk (orthogonal axes).
  • Internal memory banks — extra stored slots cross-attended each forward; loops reuse weights on evolving states (some papers hybridize).
Decision models — JEV & “not a chat LM”
JEV (TypeSafe AI System One)

Bottleneck: using a full chat LLM for routing, classification, or policy choices forces you to parse free text, invites hallucinated labels, and burns latency on generation you never needed. Jev is a decision-only model: you send state (text or structured data) plus typed questions; it returns probabilities over discrete choices (and confidence), not prose.

  • Mechanism — parallel evaluation of many questions in one pass; outputs are typed (choice, score, etc.) for direct use in code.
  • Promise — calibrated routing, guardrails, and workflow branches without an LLM-as-classifier prompt hack.
  • Limits (vendor docs) — not a replacement for reasoning or open-ended generation; keep arithmetic, counting, and precise date logic in deterministic code when docs flag weakness.

Pattern: Jev (or small classifiers) for gates → LLM for language → tools for facts. Not an acronym in official branding — a product name in a new “decision model” category.

Very small language models (sub‑3B)
Why tiny models are a separate design lane

Bottleneck: cloud APIs add cost, latency, and compliance friction; phones and laptops have tight RAM; many tasks need narrow skills, not MMLU breadth. Below ~3B parameters, quality comes less from scaling laws and more from data curation, distillation, and inference stack (quantization, kernels).

Chooser — what to study for which pain
  • Serving long chats cheaply → GQA/MLA, KV quant, context trimming; maybe sliding window arch.
  • 100k+ document ingestion → long-context RoPE + RAG (retrieval still usually beats brute-force context).
  • GPU budget fixed, quality hungry → MoE APIs or strong mid-size open models; distillation.
  • Agents & code → reasoning recipes + tools; model choice second to eval harness.
  • On-device / <3B → SmolLM/Phi/Qwen-mini class + INT4 + task LoRA; RAG for facts; escalate when stuck.
  • Test-time compute without longer outputs → looped depth-recurrent LMs (tune $r$); measure — one loop ≠ one layer.
  • Generation latency architecture → stay AR unless eval proves DLMs or NCM win on your length and hardware.
  • Routing & policy → decision models (Jev-style) or small classifiers; reserve LLM for language-heavy steps.
  • More knowledge in-weights without 128k context → e2e memory banks (MoC-class) in research stacks; live doc freshness still often needs RAG.
  • Understanding the stack → read seminal table top-down, then map your bottleneck to section (b).
