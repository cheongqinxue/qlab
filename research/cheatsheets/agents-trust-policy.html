Agents — trust, safety & use policy

Issue vs tool

This page is about an agent-related problem: output and behavior that violate safety, law, or product scope. Guardrails (in the industry sense) are tools — classifiers, filters, workflow gates, policy prompts — you deploy against that problem. Do not confuse the issue with the mechanism: “we need guardrails” usually means “we need to enforce trust, safety, and use policy.”

Collective term

Harm reduction, compliance, and brand/scope limits share one goal: keep what the agent says and implies inside what your organization accepts on this surface. Shorthand: trust, safety, and use policy (separate from technical security — see system & security design).

Three pillars
Safety (harm reduction)

Block, soften, or escalate content that violates safety policies: violence, sexual content involving minors, self-harm facilitation, hate, harassment, malware instructions, and similar high-severity classes.

  • Input and output — scan user prompts and model replies; output-only gates miss jailbreak setup in the user turn.
  • Severity tiers — hard block vs warn vs log-only for internal tools.
  • Distinct from wrong facts — that is grounding & hallucination.
Compliance & regulatory policy

Rules from law, regulator, or contract: financial disclaimers, health boundaries, data minimization in replies, export controls, age gating, audit logs. The agent must not present as a licensed professional when the product is not one.

  • Often jurisdiction- and SKU-specific — same model, different policy packs per region.
  • Auditors want classifier version, policy doc hash, refusal reason codes.
Product, brand & scope

Keeps the assistant inside the job you ship: support bot vs coding agent vs HR copilot. Off-topic requests, fake capabilities (“I booked your flight” with no booking tool), or off-brand tone.

  • Scope limits — “answer only from retrieved help articles.”
  • Voice & brand — tone, forbidden phrases; HITL (human in the loop) for customer-facing copy.
Common tools (guardrails)
Layers
  1. System instructions — necessary, not sufficient.
  2. Pre-filters — on prompts before the main model call.
  3. Post-filters — classifiers on draft output; templated refusals.
  4. Workflow — human approval or narrow tools for high-risk intents.
Refuse vs redirect

Good refusals are short, non-judgmental, and actionable. Log category codes internally; avoid storing full toxic text in clear-text logs.

Eval
  • Red-team / golden violation set — prompts that must refuse — regression each release.
  • Track false positives on legitimate use.
  • Separate metrics from hallucination and tool abuse.
Chooser
  • Consumer chat → vendor safety API + post-classifier + clear refuse copy.
  • Enterprise copilot → scope + compliance first; workplace harassment/PII, not only public toxicity.
  • Internal tool → lighter moderation; still scope limits on exfiltration via creative tasks.
