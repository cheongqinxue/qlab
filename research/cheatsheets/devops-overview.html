DevOps — overview

What DevOps means here

DevOps is how you turn code into something that runs reliably for users: build it, ship it, configure it, watch it, and roll back when it breaks. It applies to web apps, APIs, data jobs, and the platform that serves ML models — not the training math itself.

MLOps (lifecycle) sits on top when the artifact is a model or RAG stack. Cloud deep learning (cloud DL) is one way to run heavy train jobs. This section is the shared basement: containers, pipelines, infra, and logs.

The loop in your head
  1. Write code in git with tests.
  2. Build an artifact (binary, container image, static site).
  3. Deploy to an environment (dev → staging → prod).
  4. Observe metrics and logs; pages when SLOs break.
  5. Change again — small diffs, automated gates, fast rollback.

“DevOps culture” is really short feedback loops and same path to prod every time, not a specific tool brand.

Environments

Development is on your laptop or a shared dev sandbox; breaking things is cheap. Staging mirrors production closely (same container, similar data shape) for final checks. Production serves real traffic; changes arrive through automation or a controlled promotion, not manual SCP. Config differences (database url, feature flags) should be environment variables, not separate forked codebases — see infrastructure.

How the DevOps pages split
Containers

Package app + dependencies into an image so “works on my machine” becomes “works on the cluster.” Containers sheet.

Kubernetes

Run many containers on a cluster: pods, Deployments, Services, Ingress, GPU scheduling, pod vs node autoscaling. Kubernetes sheet.

CI/CD

Automate test → build → deploy on every merge; that is continuous integration and delivery. CI/CD sheet.

Infrastructure

Describe servers, networks, and cloud resources as code; inject secrets safely. Infrastructure sheet.

Observability

Logs, metrics, and traces so you know what prod is doing without SSH guessing. Observability sheet; ML-specific drift → MLOps monitoring.

Security crosses everything

Auth on APIs, secrets not in git, TLS at the edge — security concepts and implement & deploy. DevOps implements; security defines what must hold.

Chooser — where to start reading

Shipping a Python API for the first time → containers, then CI/CD. Solo researcher adding a demo endpoint → containers + one PaaS deploy may be enough. Team on GCP/AWS → infrastructure + observability early. Training models only so far → cloud DL, then MLOps when you have a serve path.
