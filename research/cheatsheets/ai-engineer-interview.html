AI Engineer interview

Interview loop map

  • GenAI / RAG / agents: pipeline, eval, security — conceptual + mini design
  • System design (45–60 min): requirements, scale, data, eval, cost, failure modes
  • Serving: batching, KV cache, autoscaling, observability — senior / infra-leaning loops

Deep learning & transformers
Explain how a neural network learns — to a non-technical stakeholder.
  • Weights = knobs; training nudges them to reduce error on examples
  • Layers = stages of abstraction (simple patterns → decisions)
  • Not memorization alone: generalization needs diverse data + validation
  • Analogy: flashcards + coach correcting each round
When would you pick a CNN/Inception-style model vs a Transformer?
  • CNN: grid data (images/video frames), local patterns, efficient inductive bias
  • Inception: multi-scale features in one forward pass
  • Transformer: long context, global dependencies, parallel training — default for language/multimodal
  • Tabular: often GBM/logistic first; NN when scale + messy interactions justify cost
Why is Adam so common in deep learning?
  • Per-parameter learning rate from gradient + squared-gradient EMAs
  • Handles sparse/noisy grads better than fixed-lr SGD in many DL tasks
  • Production: prefer AdamW (weight decay decoupled from adaptive step)
  • Watch: grad clip, ε, stale second moments — see failure modes
What is self-attention, in one interview answer?
  • Each token compares itself (query) to all keys → softmax weights → weighted sum of values
  • Learns which context tokens matter for this position
  • Multi-head = several relation types in parallel
  • Cost scales with sequence length (quadratic in full attention)
Why mask the decoder during training?
  • Causal mask: position t cannot attend to tokens > t
  • Without it, model “sees the answer” — not true next-token prediction
  • Encoder-only (BERT): bidirectional, no causal mask — different pretraining objective
  • Seq2seq: decoder self-attn masked; cross-attn to encoder unmasked
What breaks when you keep making the network deeper?
  • Vanishing/exploding gradients — residuals, norm, init, clipping
  • Overfit — data, regularization, early stop
  • Train/serve cost — latency, memory; distill / quantize / KV cache at inference
  • Diminishing returns — measure on val, not depth for its own sake
ML system design
Design a multimodal GenAI feature for an e-commerce site. How do you handle bias?
  • Human approval before customer-facing copy; style/brand guardrails
  • Slice eval: locale, gender presentation, product category, language
  • Red-team prompts; refusal policy; escalation for sensitive categories
  • Metrics: override rate, harm reports, business KPI vs control — not demo quality alone
  • Ask: who is harmed first if the model is wrong?
Design a RAG chatbot over internal financial documents.
  • Ingest → chunk → embed → vector index + metadata (tenant, date, doc ACL)
  • Retrieve top-k → optional rerank → prompt with citations only
  • Refuse or escalate when retrieval confidence low
  • Eval: recall@k, groundedness/faithfulness, human review on high-risk queries
  • Ops: index refresh, PII-safe logging, access control on retrieval
How would you use a feature store for a recommendation system?
  • Offline: point-in-time correct joins for training — no future leakage
  • Online: low-latency key lookup (user/item) at serve time
  • Registry: single definition of each feature; backfill when logic changes
  • Monitor: null rate, freshness lag, train/serve skew
Design a model to predict whether a rider accepts a trip offer.
  • Label: accept/decline; watch selection bias (only offered trips logged)
  • Features: distance, surge, time, rider history, supply/demand context
  • Latency budget for real-time scoring; fallback heuristic
  • Optimize business metric (completed trips / revenue), not raw accuracy
  • Experiment: shadow → A/B on accept rate and driver wait time
How do you tell bots from humans using browsing history?
  • Signals: timing regularity, scroll/mouse entropy, navigation patterns, velocity
  • Network/device: headless flags, datacenter IP, cookie/session reuse
  • Labels from challenges/CAPTCHA + analyst review — class imbalance likely
  • Blend rules (cheap) + model; human queue for borderline
  • Privacy: minimize retention; document purpose
Evaluation, metrics & experiments
Two teams train on the “same” dataset but get different results. Why?
  • Different splits, preprocessing, or leakage in one pipeline
  • Seeds, hyperparams, class-weight handling
  • Different metrics or bug in eval code
  • Fix: shared pipeline artifact, fixed holdout, same primary metric
AUC improved after a model change but revenue did not. What do you check?
  • Decision uses threshold/ranking — AUC may not move the action
  • Train/serve skew or wrong population in offline eval
  • Proxy metric misaligned with revenue; calibration off at operating point
  • Leakage inflated offline AUC
  • Re-run with business KPI primary on same users/time window
ROC-AUC is 0.92 but precision at your production threshold is 0.40. How can both be true?
  • AUC = ranking; precision = one cutoff — threshold may be too aggressive
  • Rare positive class → many FPs among predicted positives; check PR-AUC and base rates
  • Production base rate or calibration drift vs training
  • See metrics — ROC-AUC vs precision
Stakeholders ask why you used a neural net instead of logistic regression.
  • Nonlinear interactions / representation learning justified by val + business metric
  • Cost: data volume, latency, explainability requirements
  • If regulated: interpretability, audit trail, or hybrid (linear + NN features)
  • Show baseline comparison — NN must earn its complexity
How would you A/B test a new promotion or product feature?
  • Hypothesis + pre-registered primary metric (revenue, retention — not clicks alone)
  • Randomization unit = user (avoid session-level noise)
  • Power, duration, guardrails (latency, support tickets, fraud)
  • Novelty/primacy effects; optional long holdout
  • Peeking policy or fixed analysis date
How do you present model insights to executives who do not code?
  • Lead with decision and confidence, not algorithm name
  • One chart: impact $ or %, baseline vs new, uncertainty
  • Plain language: what changed in customer behavior
  • Risks, monitoring, and what you need from them (policy, budget)
MLOps & GenAI engineering
What is model drift and how do you respond in production?
  • Data drift: input distribution shift — PSI, slice dashboards
  • Concept drift: P(y|x) changes — performance drop on recent window
  • Alerts → diagnose slice → shadow new model or retrain trigger
  • Keep rollback artifact; document incident
What belongs in an ML CI/CD pipeline?
  • Schema/tests on data and feature code; model contract + smoke inference
  • Versioned datasets, configs, registered artifacts
  • Promote: offline gates → canary/shadow → full
  • Live monitors: latency, errors, KPI, fairness slices
Your team ships code heavily written by AI assistants. How do you validate before production?
  • Every change = PR + human review + unit/integration tests
  • SAST on merge; block critical findings
  • Security cases: injection, authz, malformed input
  • SCA on deps — verify packages exist (hallucinated names)
  • Sandbox deploy; stricter gate on auth, payments, PII paths
RAG, vectors & retrieval
Walk through the end-to-end RAG pipeline (ingestion → answer).
  • Offline: parse → structure-aware chunk + metadata → embed → upsert vector + optional BM25 index
  • Online: embed query (same model) → hybrid retrieve ~50 → rerank → prompt with numbered sources
  • Post: citations, abstain rule, faithfulness check, trace log for eval
  • See rag-systems, chunking, retrieval
Why hybrid search (dense + BM25) instead of vectors alone?
  • Dense: paraphrase and semantic match; weak on SKUs, error codes, rare acronyms, exact numbers
  • BM25: keyword/exact token recall; misses meaning across wording
  • Fuse with Reciprocal Rank Fusion (k ≈ 60) — rank-only, no score normalization
  • Cross-encoder rerank top ~50 → keep ~5; optional MMR for duplicate chunks — fusion & ranking
Bi-encoder vs cross-encoder — where does each sit?
  • Bi-encoder: embed query and doc once → cheap ANN over millions
  • Cross-encoder: joint query+doc forward → accurate, too slow for full corpus
  • Pattern: retrieve-then-rerank; ColBERT / late interaction as middle ground
  • See representations embedder catalog
How do you tune HNSW (M, ef_construction, ef_search)?
  • Trade-off: recall@k vs latency vs RAM (graph edges + layers)
  • Higher ef_search → better recall, slower queries; tune on a golden query set
  • ACL / tenant filters: prefer payload pre-filter + indexed fields — not one collection per user at B2C scale
  • Sizing: raw float32 ≈ N×D×4 bytes; add HNSW overhead — see rag-ann
pgvector vs Qdrant vs Pinecone for production RAG?
  • pgvector: small/medium scale, team already on Postgres, simpler ops — watch ANN perf at high QPS
  • Qdrant: filters, on-prem/cloud, dev-friendly; multitenancy via payload + is_tenant pre-filter
  • Pinecone: managed scale; watch namespace/collection economics and caps at many tenants
  • Decision: QPS, filter complexity, ops headcount, reindex/version strategy — rag-ann
Enforce ACLs on retrieval — zero cross-tenant leakage.
  • Store tenant/user/role on every chunk; filter in the vector DB before top-k (not “hope the LLM ignores”)
  • Identity from server session — never trust client-supplied tenant_id alone
  • Audit retrieval IDs; regression tests with forbidden cross-user queries
  • Cache keys include principal; sync ACL deletes to index — access control
Evaluate RAG: separate retrieval from generation.
  • Retrieval: recall@k, nDCG, hit rate on labeled (query, relevant_chunk_ids)
  • Generation: faithfulness/groundedness (claims ⊆ context), answer correctness vs world
  • End-to-end: task success, citation precision, abstention when context weak
  • Release gates on golden set + slice by locale/doc type — agents-model-eval
RAG answers are bad — debug in what order?
  • Classify: retrieval miss vs wrong rank vs stale doc vs generation vs prompt injection in HTML
  • Log retrieved chunk IDs + scores; inspect “right doc at rank 17” cases
  • A/B chunk size, hybrid on/off, reranker; re-embed only after retrieval metrics move
  • Do not jump straight to “bigger LLM” — rag-systems
How do you choose chunk size, overlap, and boundaries?
  • Structure-aware splits (headings, paragraphs) beat blind fixed windows for policies and docs
  • Typical band ~300–800 tokens with ~10–20% overlap; tune on golden recall@k
  • Parent–child: retrieve small chunk, return larger parent for LLM context
  • Tables/code in PDFs need specialized parsers — chunking
Vector DB returns scores — why add a cross-encoder reranker?
  • Bi-encoder similarity is fast but misorders hard pairs (“rank 17” problem)
  • Rerank top ~50 fused candidates → keep ~5; joint query+doc encoding
  • Cutoff when max score below threshold → abstain or ask clarifying question
  • See retrieval, representations
Faithfulness vs answer correctness — how are they different?
  • Faithfulness: every claim supported by retrieved context (groundedness)
  • Correctness: answer true in the real world — context may be wrong or stale
  • High faithfulness + angry users → fix retrieval/index, not only the LLM
  • Citation precision: cited span actually supports the sentence
How do you pick an embedding model (and when fine-tune)?
  • Language/domain, context length, cosine-normalized vs dot product, license and cost
  • Matryoshka dims for storage; same model + version for ingest and query
  • Fine-tune with contrastive pairs when domain vocabulary dominates (SKUs, internal jargon)
  • Embedder catalog — rag-representations
LLM agents, tools & safety
ReAct vs plan-and-execute — when do you pick each?
  • ReAct: interleaved thought → tool → observation; good for exploratory, short horizons
  • Plan-and-execute: plan once, batch tools; better when steps are known and tools expensive
  • Long horizons: replanning, step caps, human gates on irreversible actions
  • See agents-patterns
Design a production-safe tool loop (max steps, loops, bad args).
  • Hard caps: max steps, max wall time, max spend/tokens per session
  • Detect duplicate tool+args; block or require confirmation on destructive ops
  • Validate JSON/schema before execute; timeouts; user-visible fallback message
  • Idempotent reads vs transactional writes — reliability
LangGraph-style orchestration in one answer.
  • State object + nodes (functions) + edges (fixed or conditional on state)
  • Checkpointer (e.g. Postgres) for thread resume; interrupt before side effects
  • Prefer explicit graph when branches, retries, HITL — not a single while-loop script
  • See agents-patterns, memory
Short-term vs long-term memory for a support agent.
  • Short: checkpointed messages + rolling summary + “open task” fields in state
  • Long: per-user vector index of past threads; retrieve snippets, never raw dump of all history
  • Pre-login summary at session start; tools for exact order/PII fields on demand
  • Tenant isolation on every long-term retrieve — agents-memory
Prompt injection via retrieved docs or tool output — defend how?
  • Untrusted data never overrides system policy; delimit context; ignore “new instructions” in chunks
  • Least-privilege tools; no broad SQL; output filters; human approval for money/refunds
  • OWASP LLM01: direct (user) vs indirect (document) injection — both in threat model
  • See trust-policy, system-security
Evaluate agents beyond final-answer exact match.
  • Trajectory: required tools called, step budget, no infinite loops
  • Grounding when RAG involved; task success on replayed tickets
  • LLM-as-judge + human calibration set; production failure mining into CI
  • See agents-model-eval, grounding
Guardrails vs offline eval — why do you need both?
  • Guardrails: runtime block/modify on policy violations (latency-sensitive)
  • Offline eval: regression gates before ship; golden set + slice metrics
  • Novel jailbreaks slip eval → online sampling, human review queue, update gates
  • Balance false refusal vs safety on high-stakes intents — trust-policy
Human-in-the-loop before irreversible actions (refund, cancel, ship).
  • Graph interrupt after intent clear, before tool side effect; durable thread ID
  • User approve / edit / reject; timeout → escalate, do not auto-run
  • Idempotent tool design — resume after interrupt may re-run prior nodes
  • Auto-approve only under hard caps enforced in code, not prompt — patterns
Production LLM serving
Where does vLLM end and Ray Serve begin?
  • K8s: schedules GPU nodes/pods; Ray: places actors; Serve: deployment graph, routing, replica autoscale
  • vLLM: continuous batching, PagedAttention, KV cache on GPU
  • Skip Ray when one model + simple Deployment + ingress is enough
  • Queues: BFF limits → Serve max_queued_requests → vLLM max-num-seqs — Ray + vLLM
Explain PagedAttention and why KV cache limits concurrency.
  • KV stored in fixed blocks with block table — less fragmentation than one contiguous buffer per seq
  • Memory ~ layers × heads × head_dim × seq × dtype × 2 (K and V)
  • Often hits KV cap before compute-bound; prefix caching shares blocks across prompts
  • See efficiency, serving
TTFT vs TPOT — what breaks when each degrades?
  • TTFT: queue + prefill; up with saturation or long prompts
  • TPOT / inter-token latency: decode batching and KV pressure
  • Instrument per stage; SLO on p95/p99 — not mean latency
  • See observability
P99 TTFT spikes but TPOT is fine — debug in what order?
  • Queue depth and admission control; cold start / new replicas not ready
  • Prefill head-of-line: long prompts, chunked prefill settings
  • KV occupancy and preemption rate — not visible on GPU-util-only dashboards
  • Post-deploy: warm replicas before traffic; cap queue → 429 — runbooks
K8s autoscaling for LLMs — why not GPU utilization alone?
  • GPU util lags and hides queue buildup; scale on waiting requests, batch depth, TTFT p95
  • Scale-down stabilization — avoid flapping; minReplicas / warm pool for cold start
  • Pending replica storm: GPUs unavailable → cap replicas, shed load, drain non-critical deployments
  • Feature flags at BFF to stop retry storms — failure runbooks
Design an LLM inference API (streaming, multi-tenant, SLOs).
  • Gateway: auth, quotas, validation, SSE streaming, cancellation propagates to free KV
  • Admission control + bounded queues; 429 vs unbounded wait
  • Model registry, canary, shadow traffic, rollback artifact pinned
  • Separate interactive vs batch priority classes — common 45–60 min senior prompt
Training, PEFT & ML depth (common coding / whiteboard)
Find the bugs in this PyTorch training loop.
  • Missing optimizer.zero_grad(); logging loss tensor vs loss.item()
  • model.train() / eval() + torch.no_grad() for validation
  • Wrong accuracy denominator; logits vs softmax for CE
  • See training-loop, failure modes
LoRA — formula, init, rank, when to merge for serving.
  • ΔW = BA, rank r; A random, B zero → start at base weights
  • Scale α/r; target q_proj/v_proj typical; QLoRA when VRAM-bound
  • Merge adapters into base for lowest latency unless base is quantized in a way that forbids it
  • See PEFT
Define prediction time and give two leakage examples.
  • Only features known at decision time T; label must not appear in features
  • Obvious: target column in X; subtle: aggregates including events after T
  • Fit preprocessors inside CV folds; group splits by user/entity
  • See generalization, testing-ml
How is ML CI/CD different from normal software CI/CD?
  • Three moving parts: code, data, model — any can change behavior independently
  • Non-deterministic training; need data/schema tests and reproducible artifacts
  • Gates: offline metrics → register → canary/shadow → promote; prediction contract tests
  • See pipelines, devops-cicd
System design prompts (practice — 45–60 min)
Agentic e-commerce support (~100k contacts/day, refunds via tools).
  • Score: identity before account actions, refund caps in code, audit trail, eval on ticket replay
  • Probe: walk one refund with latency budget; injection via order notes; 10× traffic plan
  • Aligns with agents-security + order APIs
Enterprise doc RAG (millions of docs, ACL per user, <3s p95 chat).
  • Hybrid + rerank; mandatory metadata filter on every query; legal hold / deletion propagation
  • Probe: sharding index; hallucination metrics; block release if ACL-leak tests fail
  • See rag-systems, access control
IDE code completion (p95 ghost text <800ms, 100k+ devs).
  • Prefix cache / KV affinity routing; small model for completion, large for chat
  • Client secret redaction; acceptance rate + retention as online metrics
  • Fail silent on timeout — user keeps typing
Real-time fraud scoring (p99 ≤50ms, 10k RPS, delayed labels).
  • Streaming features (Redis); GBDT + rules; shadow deploy; fail-open vs fail-closed by tier
  • Not LLM-first — tests classical ML + infra depth
  • See monitoring, metrics
Conversational product discovery (“gift under $40, arrives Friday”).
  • NL → structured filters + semantic retrieval over large SKU index; grounded product cards
  • Never promise delivery the catalog cannot support; show stock/shipping freshness
  • Probe: hybrid search latency budget; hallucinated product attributes
Developer docs assistant (versioned APIs, 500 QPS, cite or refuse).
  • Chunk by version + endpoint; refuse when retrieval score low; mandatory citations
  • CI eval on every doc publish webhook; route simple queries to smaller model
  • Multi-hop “v2 vs v3 migration” needs planner or decomposed sub-queries
Five probes interviewers reuse on any design.
  • End-to-end latency budget per hop
  • Retrieval failed — metric and fix order
  • Prompt injection trust boundary
  • 10× traffic — first bottleneck
  • Ship v2 — shadow/canary gates and rollback trigger
Behavioral & collaboration
Requirements were vague and the deadline was fixed. What did you do?
  • STAR: narrow to measurable outcome with sponsor
  • Time-box discovery; deliver thin vertical slice first
  • Written assumptions; explicit out-of-scope
  • Communicate trade-offs early — date vs scope vs quality
You disagreed with a senior engineer on the technical approach.
  • Data or experiment to resolve — not opinion alone
  • Align on criteria: risk, cost, maintainability, user impact
  • Disagree and commit once decided; document decision
  • Escalate only if risk to users, security, or ethics
You had no direct authority but needed another team to prioritize your work.
  • Shared goal in their language (risk, revenue, SLA)
  • Small ask first; prove value
  • Executive sponsor if blocked
  • Make work easy: clear spec, estimates, rollback plan
Critical training data was missing or badly labeled.
  • Quantify impact on metric slices
  • Options: relabel budget, weak labels, transfer learning, rule baseline
  • Ship with confidence bounds + human review where error is costly
  • Transparent to stakeholders — no silent failure

  • Responsible angle if user-facing (fairness, privacy, fallback)
