AI Engineer interview

Deep learning & transformers
Explain how a neural network learns — to a non-technical stakeholder.
  • Weights = knobs; training nudges them to reduce error on examples
  • Layers = stages of abstraction (simple patterns → decisions)
  • Not memorization alone: generalization needs diverse data + validation
  • Analogy: flashcards + coach correcting each round
When would you pick a CNN/Inception-style model vs a Transformer?
  • CNN: grid data (images/video frames), local patterns, efficient inductive bias
  • Inception: multi-scale features in one forward pass
  • Transformer: long context, global dependencies, parallel training — default for language/multimodal
  • Tabular: often GBM/logistic first; NN when scale + messy interactions justify cost
Why is Adam so common in deep learning?
  • Per-parameter learning rate from gradient + squared-gradient EMAs
  • Handles sparse/noisy grads better than fixed-lr SGD in many DL tasks
  • Production: prefer AdamW (weight decay decoupled from adaptive step)
  • Watch: grad clip, ε, stale second moments — see failure modes
What is self-attention, in one interview answer?
  • Each token compares itself (query) to all keys → softmax weights → weighted sum of values
  • Learns which context tokens matter for this position
  • Multi-head = several relation types in parallel
  • Cost scales with sequence length (quadratic in full attention)
Why mask the decoder during training?
  • Causal mask: position t cannot attend to tokens > t
  • Without it, model “sees the answer” — not true next-token prediction
  • Encoder-only (BERT): bidirectional, no causal mask — different pretraining objective
  • Seq2seq: decoder self-attn masked; cross-attn to encoder unmasked
What breaks when you keep making the network deeper?
  • Vanishing/exploding gradients — residuals, norm, init, clipping
  • Overfit — data, regularization, early stop
  • Train/serve cost — latency, memory; distill / quantize / KV cache at inference
  • Diminishing returns — measure on val, not depth for its own sake
ML system design
Design a multimodal GenAI feature for an e-commerce site. How do you handle bias?
  • Human approval before customer-facing copy; style/brand guardrails
  • Slice eval: locale, gender presentation, product category, language
  • Red-team prompts; refusal policy; escalation for sensitive categories
  • Metrics: override rate, harm reports, business KPI vs control — not demo quality alone
  • Ask: who is harmed first if the model is wrong?
Design a RAG chatbot over internal financial documents.
  • Ingest → chunk → embed → vector index + metadata (tenant, date, doc ACL)
  • Retrieve top-k → optional rerank → prompt with citations only
  • Refuse or escalate when retrieval confidence low
  • Eval: recall@k, groundedness/faithfulness, human review on high-risk queries
  • Ops: index refresh, PII-safe logging, access control on retrieval
How would you use a feature store for a recommendation system?
  • Offline: point-in-time correct joins for training — no future leakage
  • Online: low-latency key lookup (user/item) at serve time
  • Registry: single definition of each feature; backfill when logic changes
  • Monitor: null rate, freshness lag, train/serve skew
Design a model to predict whether a rider accepts a trip offer.
  • Label: accept/decline; watch selection bias (only offered trips logged)
  • Features: distance, surge, time, rider history, supply/demand context
  • Latency budget for real-time scoring; fallback heuristic
  • Optimize business metric (completed trips / revenue), not raw accuracy
  • Experiment: shadow → A/B on accept rate and driver wait time
How do you tell bots from humans using browsing history?
  • Signals: timing regularity, scroll/mouse entropy, navigation patterns, velocity
  • Network/device: headless flags, datacenter IP, cookie/session reuse
  • Labels from challenges/CAPTCHA + analyst review — class imbalance likely
  • Blend rules (cheap) + model; human queue for borderline
  • Privacy: minimize retention; document purpose
Evaluation, metrics & experiments
Two teams train on the “same” dataset but get different results. Why?
  • Different splits, preprocessing, or leakage in one pipeline
  • Seeds, hyperparams, class-weight handling
  • Different metrics or bug in eval code
  • Fix: shared pipeline artifact, fixed holdout, same primary metric
AUC improved after a model change but revenue did not. What do you check?
  • Decision uses threshold/ranking — AUC may not move the action
  • Train/serve skew or wrong population in offline eval
  • Proxy metric misaligned with revenue; calibration off at operating point
  • Leakage inflated offline AUC
  • Re-run with business KPI primary on same users/time window
Stakeholders ask why you used a neural net instead of logistic regression.
  • Nonlinear interactions / representation learning justified by val + business metric
  • Cost: data volume, latency, explainability requirements
  • If regulated: interpretability, audit trail, or hybrid (linear + NN features)
  • Show baseline comparison — NN must earn its complexity
How would you A/B test a new promotion or product feature?
  • Hypothesis + pre-registered primary metric (revenue, retention — not clicks alone)
  • Randomization unit = user (avoid session-level noise)
  • Power, duration, guardrails (latency, support tickets, fraud)
  • Novelty/primacy effects; optional long holdout
  • Peeking policy or fixed analysis date
How do you present model insights to executives who do not code?
  • Lead with decision and confidence, not algorithm name
  • One chart: impact $ or %, baseline vs new, uncertainty
  • Plain language: what changed in customer behavior
  • Risks, monitoring, and what you need from them (policy, budget)
MLOps & GenAI engineering
What is model drift and how do you respond in production?
  • Data drift: input distribution shift — PSI, slice dashboards
  • Concept drift: P(y|x) changes — performance drop on recent window
  • Alerts → diagnose slice → shadow new model or retrain trigger
  • Keep rollback artifact; document incident
What belongs in an ML CI/CD pipeline?
  • Schema/tests on data and feature code; model contract + smoke inference
  • Versioned datasets, configs, registered artifacts
  • Promote: offline gates → canary/shadow → full
  • Live monitors: latency, errors, KPI, fairness slices
Your team ships code heavily written by AI assistants. How do you validate before production?
  • Every change = PR + human review + unit/integration tests
  • SAST on merge; block critical findings
  • Security cases: injection, authz, malformed input
  • SCA on deps — verify packages exist (hallucinated names)
  • Sandbox deploy; stricter gate on auth, payments, PII paths
Behavioral & collaboration
Requirements were vague and the deadline was fixed. What did you do?
  • STAR: narrow to measurable outcome with sponsor
  • Time-box discovery; deliver thin vertical slice first
  • Written assumptions; explicit out-of-scope
  • Communicate trade-offs early — date vs scope vs quality
You disagreed with a senior engineer on the technical approach.
  • Data or experiment to resolve — not opinion alone
  • Align on criteria: risk, cost, maintainability, user impact
  • Disagree and commit once decided; document decision
  • Escalate only if risk to users, security, or ethics
You had no direct authority but needed another team to prioritize your work.
  • Shared goal in their language (risk, revenue, SLA)
  • Small ask first; prove value
  • Executive sponsor if blocked
  • Make work easy: clear spec, estimates, rollback plan
Critical training data was missing or badly labeled.
  • Quantify impact on metric slices
  • Options: relabel budget, weak labels, transfer learning, rule baseline
  • Ship with confidence bounds + human review where error is costly
  • Transparent to stakeholders — no silent failure
Describe an end-to-end ML or AI project you are proud of.
  • Problem → baseline → iteration → deployment (even pilot)
  • Your specific ownership (data, model, infra, stakeholder)
  • Metric moved; what you’d improve second time
  • Responsible angle if user-facing (fairness, privacy, fallback)
You are pair programming in the interview. What do they want to see?
  • Think aloud: intent before typing
  • Clarify constraints and edge cases
  • Small steps; run/test often
  • Invite feedback — collaboration over solo heroics
