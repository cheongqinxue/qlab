GenAI — attack vectors & detection

Scope

These threats sit on top of normal application security (broken AuthZ, SQL injection, leaked API keys). GenAI adds paths where untrusted text becomes instructions or indexed knowledge, and where model outputs drive side effects. Detection mixes security monitoring (signals, takedowns) with product eval (red teams, regression sets). Mitigations for agents and tools live on agents — system security; ingest and index controls on RAG ingest pipeline.

Prompt injection
Direct injection

The user tries to override system policy in the chat input (“ignore previous rules”, role-play as admin, exfiltrate secrets). Detect: rule-based and ML classifiers on input; canary system strings that must never appear in model output; alert on spikes in jailbreak keyword rate per tenant; sample traces for human review. Signal: sudden increase in tool calls to sensitive endpoints after long user preambles; refusal bypass rate vs baseline.

Indirect injection (RAG, email, web, tools)

Adversarial instructions live in documents, tickets, web pages, or tool responses that later enter context. The user question may be innocent. Detect: scan at ingest and again on retrieved chunks (see ingest sheet); log retrieved chunk ids when model proposes high-impact actions; compare action intent to user query (embedding or classifier mismatch); honey-documents that alarm when retrieved and cited. Signal: email or export tools invoked after KB retrieval from a single new or low-trust source.

Data poisoning & knowledge-base abuse
Index poisoning

Attacker publishes or edits content so retrieval surfaces malicious or false passages (policy text, injection paragraphs, SEO-style spam). Works even when the chat model is aligned if the app trusts retrieved text. Detect: new-source volume alerts; classifier scores on ingest; retrieval of docs from untrusted tiers spiking; user reports + faithfulness drops on queries that cite affected doc ids; periodic diff of high-traffic chunks vs prior version. Respond: ACL block source, quarantine collection, re-embed after purge; see ingest pipeline for quarantine workflow.

Training / fine-tuning poisoning

Malicious or biased examples in SFT/RLHF data teach harmful compliance (always refund, leak format, ignore refusals). Detect: offline eval on refusal and policy-violation sets before and after adapter merge; statistical outliers in training JSONL (toxic n-grams, abnormal resolution rates); provenance audit on who submitted rows. Less common in production than index poisoning but high impact when it lands.

Tool, agent, and exfiltration paths
Tool misuse and privilege escalation

Model calls tools with attacker-chosen arguments (wrong ids, bulk export, path traversal in filenames). Often combined with injection. Detect: AuthZ denials logged and alerted; anomaly on tool argument patterns (recipient domains, row counts); rate limits tripped per user; compare tool calls to allowed schema and allowlists. Harness must enforce scope — detection catches what slips through.

PII and secret exfiltration

Model echoes training or context secrets into output, logs, or third-party LLM APIs; users trick the bot into repeating other users’ data. Detect: DLP scanners on output and on outbound LLM payloads; regex/entity alerts on SSN, card patterns; cross-tenant retrieval tests in CI; log redaction audits. Signal: support tickets citing “bot showed another customer’s order.”

Availability, cost, and model abuse
Denial of wallet and denial of service

Long contexts, agent loops, or parallel sessions burn GPU and budget; retry storms amplify load. Detect: tokens per session, steps per thread, cost per tenant vs baseline; queue depth and 429 rate; same IP many sessions. Pair with agents — reliability.

Model extraction and probing

Systematic queries to reconstruct behavior or distill the model. Detect: high-volume templated queries from one principal; unusual embedding of system prompt fragments in user input; rate limits and bot detection at edge.
