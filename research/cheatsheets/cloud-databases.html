Managed OLTP/NoSQL/cache offerings on AWS, GCP, Azure, and selected multi-cloud Postgres/MySQL platforms (2024–2026). Dollar figures change — verify on vendor pricing pages.

Cloud databases

Scope

This sheet compares vendor-operated database services (not self-managed VMs). Focus: transactional workloads, managed Postgres/MySQL/SQL Server, cloud-native NoSQL, and developer-centric Postgres platforms. Numbers are structural (pricing models and representative list prices where cited); always confirm region, edition, and discounts on official pages before budgeting.

Decision framework
  1. Engine fidelity: Need vanilla Postgres/MySQL/SQL Server → RDS, Cloud SQL, Azure Flexible Server. Need AWS-optimized MySQL/PG → Aurora. Need global SQL scale → Spanner or Cosmos (RU/vCore model tradeoffs).
  2. Traffic shape: Steady 24/7 → provisioned instances + reserved/CUD. Spiky or dev/test → serverless (Aurora serverless, Azure SQL serverless, Neon CU-hours, DynamoDB on-demand).
  3. Ops boundary: Full platform (auth, realtime) → Supabase. Branching + scale-to-zero Postgres → Neon. Sharded MySQL/Vitess or metal → PlanetScale. Stay in one cloud VPC → hyperscaler native beats egress-heavy multi-cloud.
  4. Consistency & scale-out: Single-writer OLTP → managed relational. Horizontal writes beyond one node → Aurora Limitless, Citus/Elastic Clusters, Vitess, DynamoDB, or Spanner — each with different SQL semantics and migration cost.
  5. Total cost: Model compute, storage, I/O/IOPS, backup retention, cross-AZ, cross-region replication, and egress together; cheapest compute SKU often loses on I/O or NAT.
Cost gotchas (all clouds)
  • Egress: Client or app tier outside the DB VPC/region pays per-GB outbound (Supabase Pro includes 250 GB then overage; Azure/GCP/AWS DB pricing pages bill WAN egress separately from compute).
  • NAT gateways: Private-subnet apps reaching the public internet (or cross-zone hairpin) accrue NAT processing + egress — common surprise next to “cheap” db.t4g.micro RDS.
  • Multi-AZ / HA: Aurora replicas, Cloud SQL HA, Azure zone-redundant Flexible Server, and PlanetScale’s 3-node Vitess cluster multiply compute; storage may duplicate too.
  • I/O vs IOPS: Aurora Standard charges per million I/O; Aurora I/O-Optimized trades higher storage rate for zero per-I/O fees. RDS gp3 vs io2 Block Express: provisioned IOPS billed whether used.
  • Backup & PITR: Backup storage beyond free allowance (often tied to DB size) and long PITR windows (Neon history storage, Supabase PITR add-on) add steady cost.
  • Idle minimums: Provisioned DynamoDB RCU/WCU, always-on RDS, and Azure SQL serverless minimum vCores while online still bill; Neon/Supabase scale-down helps only when compute actually suspends.
Cross-cloud comparison (OLTP Postgres)

Same engine, different packaging — pick by cloud residency and traffic shape:

  • AWS RDS PostgreSQL: Per-hour instance + gp3/io storage; closest to “Postgres on a VM” with AWS integrations. vs Aurora PG if you want storage auto-grow, fast failover, Global Database, or Limitless sharding.
  • GCP Cloud SQL PG: vCPU + memory + disk; Enterprise Plus tier for higher availability/performance. vs AlloyDB for Google’s disaggregated storage + higher throughput OLTP analytics blend.
  • Azure Flexible Server PG: vCore-hour + GiB-month storage; stop/start and burstable SKUs. vs Elastic Clusters (Citus) for sharded Postgres (Cosmos DB for PostgreSQL is retiring — migrate to Elastic).
  • Neon / Supabase: Multi-cloud Postgres; Neon bills CU-hours + GB-month; Supabase bills org plan + per-project compute (Micro from ~$10/mo) + disk/egress quotas.
Amazon RDS (MySQL, PostgreSQL, MariaDB, SQL Server, Oracle)

What: Managed single-primary relational instances; you choose engine version, instance class, and EBS-backed storage (gp3, io2).

Pricing: DB instance-hours (per-second, 10-minute minimum after changes) + provisioned storage (GiB-month) + optional provisioned IOPS + backup beyond free tier + data transfer. Reserved Instances / Savings Plans reduce steady compute. Example list rates (US East, verify): db.t4g.micro often cited ~$0.016/hr; larger classes scale linearly — see engine-specific pages.

When: Standard lift-and-shift OLTP, need specific extensions or minor version control, or want lowest conceptual overhead vs Aurora features.

2024–2026: Broad RDS list-price reductions (May 2025 AWS price list updates). gp3/io2 Block Express remains default guidance for I/O-heavy workloads.

Sentiment: G2/AWS peer reviews praise operational maturity; cost reviews often flag Multi-AZ + storage growth — align instance right-sizing with AWS Compute Optimizer / Performance Insights.

Amazon Aurora (MySQL & PostgreSQL)

What: AWS storage/compute-separated cluster; compatible with MySQL or PostgreSQL wire protocols; optional Global Database, ML integration, and Limitless horizontal scale (PG).

Pricing: (1) Provisioned — per DB instance-hour; (2) Serverless — per ACU-hour (≈2 GiB RAM + CPU per ACU, billed per second); storage GiB-month; Aurora Standard adds per-million I/O, I/O-Optimized flattens I/O into storage rate; backups + cross-region replication extra. Steady 24/7 workloads: AWS blog guidance favors provisioned + RI; spiky workloads favor serverless ACUs.

When: High availability in AWS, read replicas, serverless scaling, or PG Limitless for single-database sharding vs DIY Citus.

2024–2026: Aurora PostgreSQL Limitless GA (Oct 2024); region expansion and PG 16.x support through 2025; “Serverless v2” branding consolidated to Aurora serverless (2026 docs).

Sentiment: re:Invent / AWS Database Blog positioning emphasizes serverless + Limitless for variable and mega-scale PG; third-party FinOps posts still warn to model I/O-heavy Standard vs I/O-Optimized explicitly.

Amazon DynamoDB

What: Fully managed key-value and document store; single-digit ms at scale; optional DynamoDB Streams, DAX cache, Global Tables.

Pricing: On-demand — pay per read/write request unit (4 KiB read chunks, 1 KiB write chunks); Provisioned — hourly RCU/WCU whether consumed. Storage (Standard vs Infrequent Access), backups, PITR, and global replication billed separately. Nov 2024: AWS cut on-demand throughput ~50% and reduced global tables replication write pricing.

When: Unpredictable traffic, serverless microservices, gaming/session stores — vs RDS when you need ad hoc SQL joins. vs DocumentDB if you must keep MongoDB API on AWS.

2024–2026: AWS recommends on-demand as default for most new workloads post-2024 price cuts; provisioned + auto scaling for flat high utilization.

Sentiment: Practitioner blogs (AWS Database Blog, re:Post) highlight simpler ops; design reviews note hot-partition and GSIs design still require NoSQL discipline — not a drop-in RDBMS replacement.

AWS (other managed data stores)
  • DocumentDB: MongoDB-compatible API on AWS; cluster instance-hours + storage + I/O; use when Mongo API must stay in-VPC on AWS (verify compatibility matrix for your driver features).
  • ElastiCache / MemoryDB: Redis/Memcached/Valkey vs durable Redis — node-hours; MemoryDB adds Multi-AZ durability premium vs ephemeral cache.
  • Redshift Serverless / provisioned: Analytics warehouse — RPU-hour or instance-hour + storage; not OLTP substitute.
  • Neptune: Graph (Gremlin/openCypher/SPARQL) — instance-hours; vs Aurora for relational.

Pricing hub: aws.amazon.com/rds/pricing/, DynamoDB and ElastiCache pricing pages.

Google Cloud SQL

What: Managed MySQL, PostgreSQL, SQL Server — familiar single-instance or HA regional instances.

Pricing: vCPU + memory (per-second billing while running) + storage + networking; Enterprise vs Enterprise Plus editions differ in SLA/features and CPU/RAM rates. HA doubles effective compute. Extended support surcharge for EOL major versions (waived temporarily in early 2025 — check current policy).

When: Default relational choice on GCP when AlloyDB features aren’t needed; SQL Server workloads requiring licensed images.

2024–2026: Edition split aligns with higher-tier HA/performance SKUs; extended support billing is an operational planning item for older PG/MySQL majors.

Sentiment: GCP docs emphasize predictable vCPU billing; community comparisons often pit Cloud SQL vs AlloyDB on throughput per dollar for write-heavy PG.

Google AlloyDB for PostgreSQL

What: PostgreSQL-compatible service with disaggregated, auto-scaling storage and read pools; marketed for demanding OLTP + near-real-time analytics.

Pricing: vCPU-hour + GiB-hour memory + shared storage (pay used, not per read replica) + backup + egress. HA primary uses two nodes (active + standby) — doubles CPU/RAM charge vs zonal. Example US list (verify region): on-demand vCPU often ~$0.066/hr tier before CUDs.

When: Postgres on GCP needing higher performance than Cloud SQL or columnar/HTAP integration; not a Spanner replacement for global strong consistency at planet scale.

2024–2026: Continued alignment with PG versions and AI/ML analytics narratives in Google Cloud Next summaries; check release notes for columnar/vector features per quarter.

Sentiment: Benchmark-oriented blogs report strong PG compatibility with migration tooling; FinOps reviews appreciate lack of opaque I/O surcharges vs some Aurora modes.

Google Cloud Spanner

What: Globally distributed, horizontally scaled relational DB (GoogleSQL or PostgreSQL interfaces); external consistency.

Pricing: Editions (Standard, Enterprise, Enterprise Plus) — compute per node/replica-hour, storage GiB-month, backup, cross-region replication, egress. Multi-region configs multiply replicas (e.g., 5+ replicas). 1- and 3-year CUDs (~20% / ~40%). Enterprise adds graph, search, vector; Enterprise Plus adds highest SLA multi-region + geo-partitioning.

When: Global OLTP with strict consistency and tolerance for Spanner SQL/dialect constraints; vs Cloud SQL/AlloyDB for single-region Postgres familiarity.

2024–2026: Spanner editions GA narrative (post-Sep 2024) — tier picking is the main cost lever; PostgreSQL dialect and vector/search features expanded in Enterprise tiers.

Sentiment: Gartner/peer comparisons often cite Spanner for mission-critical global scale; developers note schema/query differences vs vanilla Postgres worth POC time.

Google Firestore & Bigtable (document / wide-column)

Firestore (Native): Serverless document DB — per 100k reads/writes/deletes + storage + egress; daily free quota (e.g., 50k reads/day on native mode — verify). Firestore Enterprise + MongoDB compatibility (GA 2025): read/write units (4 KiB / 1 KiB chunks) — different from classic document counts.

When: Mobile/web sync, Firebase apps, or Mongo API on Google without Atlas egress to another cloud.

Bigtable: Provisioned nodes + storage — high-throughput time series/wide-column; not transactional RDBMS.

Azure Database for PostgreSQL — Flexible Server

What: Managed Postgres with configurable maintenance, HA options, stop/start, burstable SKUs.

Pricing: vCore-hours + provisioned storage (GiB-month) + backup storage consumed; zone-redundant HA increases compute. Savings plans / reserved capacity for steady loads. Microsoft lists separate line items on invoice (compute vs storage vs backup).

When: Default Postgres on Azure; prefer over single-server (retired) for new deployments.

2024–2026: Elastic Clusters (Citus) promoted as strategic sharded Postgres; newer PG versions (17+) on Elastic vs legacy Cosmos PG.

Sentiment: Microsoft Learn migration guides emphasize Elastic Clusters cost simplicity (no separate coordinator surcharge vs Cosmos DB for PostgreSQL); G2-style reviews praise Flexible Server ops, with cost notes on HA + storage autogrow planning.

Azure SQL Database

What: Managed SQL Server engine — DTU (legacy sizing) or vCore models; tiers General Purpose, Business Critical, Hyperscale (up to ~100 TB storage scale-out architecture).

Pricing: Provisioned vCore per second or hour; Serverless — bill greater of CPU vs memory (memory normalized at 3 GiB per vCore), per-second, auto-pause = compute $0 (storage only). Hyperscale serverless supported; auto-pause on Hyperscale was preview — check current GA status. Storage on Hyperscale: pay allocated GB between 10 GB and max tier limit.

When: Microsoft stack, .NET apps, T-SQL features; Hyperscale for very large single DBs; vs Flexible Server when Postgres is required.

2024–2026: Ignition-era Hyperscale pricing simplification still referenced in docs; serverless + Hyperscale combo marketed for variable analytics/OLTP hybrids.

Azure Cosmos DB

What: Multi-model global database — API choice locks pricing model: NoSQL/Mongo(RU)/Cassandra/Gremlin/Table on request units (RU/s); PostgreSQL/Mongo(vCore)/Garnet on vCore + disk per node.

Pricing: RU APIs — provisioned RU/s (manual or autoscale max), serverless option, consumed storage per region, multi-region multiplier, egress. vCore APIs — cluster nodes + disk; Cosmos DB for PostgreSQL is retiring — new deployments blocked; migrate to Elastic Clusters on Flexible Server.

When: Global low-latency NoSQL with SLA’d multi-region writes; vs Azure SQL for relational T-SQL; vs Flexible Server for Postgres compatibility.

Sentiment: Enterprise reviews cite strong global distribution; developer forums frequently discuss RU provisioning discipline and partition key design to avoid throttling bills.

Neon (serverless Postgres)

What: Postgres with separated storage/compute, branching, scale-to-zero; runs on AWS/Azure regions (multi-cloud control plane).

Pricing (usage-based, verify): CU-hour (1 CU ≈ 1 vCPU + 4 GiB RAM) — Launch ~$0.106/CU-hr, Scale ~$0.222/CU-hr (2025 reductions); storage ~$0.35/GB-month; instant-restore/history storage ~$0.20/GB-month; branch-hours beyond quota ~$0.002/hr. Free tier: projects + CU-hours/month + per-project storage caps. Post-Databricks acquisition: enterprise features folded into Scale tier (per Neon blog, 2025).

When: Dev/preview environments, intermittent SaaS, many DB branches — vs Supabase if you need bundled Auth/Storage; vs Cloud SQL if you must keep all data in GCP-only billing.

Sentiment: Hacker News / developer blogs praise branching UX and scale-to-zero; production users note monitoring cold-start latency after idle suspend.

Supabase (Postgres platform)

What: Managed Postgres per project plus optional Auth, Storage, Realtime, Edge Functions — still usable as DB-only via connection string.

Pricing: Org plans — Free ($0, 500 MB DB, pauses after 1 week idle, 2 active free projects); Pro from $25/mo includes $10 compute credit (covers one Micro ~$10/mo), 8 GB disk/project, 250 GB egress; extra projects add compute instances; disk overage ~$0.125/GB; PITR add-on priced separately (~$100/mo per retention block on Pro — verify). Not pure serverless — each project is a dedicated compute size table (Micro → 16XL).

When: Greenfield apps wanting Postgres + auth/storage in one bill; vs Neon for deeper branching/storage architecture and CU billing.

2024–2026: Org-based billing and compute credit model documented in platform guides; branching billed per branch-hour on paid tiers.

Sentiment: G2 categories show strong SMB/developer satisfaction for velocity; cost threads warn that each production project needs its own compute line item.

PlanetScale (Vitess MySQL, Postgres, Neki)

What: Managed Vitess (MySQL-compatible) historically; 2025 GA push for sharded Postgres and Neki engine; database branching on Vitess; metal SKUs with local NVMe.

Pricing: No free tier (Hobby retired 2024). Base plan: Vitess non-metal clusters from ~$39/mo (PS-10, 3-node: primary + 2 replicas) — verify SKU table; storage often 10 GB included then per-GB; ~1440 dev branch hours/mo included; single-node Postgres from ~$5/mo entry (docs). Metal clusters priced higher with bundled NVMe tiers.

When: Large MySQL needing online schema change + horizontal sharding; vs Aurora for AWS-native; vs RDS when Vitess workflow (deploy requests) fits team culture.

2024–2026: Postgres GA (InfoQ/industry coverage Oct 2025); Cloudflare Workers integration for edge-adjacent full-stack; hobby-plan removal remains a polarizing tradeoff (paid minimum for production seriousness).

Sentiment: Developers praise branching and ops automation; price-sensitive hobbyists migrated to alternatives when free tier ended.

MongoDB Atlas (multi-cloud)

What: Managed MongoDB on AWS, GCP, Azure — replica sets and sharded clusters; Atlas Search/Vector as add-ons.

Pricing: Free M0; Flex ~$0.011/hr with ~$8–$30/mo cap for bursty dev/test; Dedicated from ~$0.08/hr (M10 ≈ $56.94/mo list — verify) + storage + backup + egress (Free/Flex egress often free). Atlas Infinite (2025): decoupled compute/storage for AI/agentic burst scaling on M10+.

When: Document model across clouds with unified ops; vs Firestore Mongo-compat on GCP; vs DocumentDB on AWS if Atlas egress/cost acceptable.

Sentiment: Gartner Peer Insights / G2 highlight ease of multi-cloud; FinOps blogs recommend Flex for non-prod and reserved capacity for steady prod tiers.

Free tiers & entry points (verify limits)
  • AWS: RDS/Aurora — typically 12-month Free Tier credits for new accounts (engine/time caps); DynamoDB always-free tier for on-demand capacity units in home region.
  • GCP: Firestore daily free operations + 1 GiB; Cloud SQL sometimes promotional credits — check current SKU promos.
  • Azure: Cosmos DB free tier (RU account); Flexible Server often trial credits via subscription offers.
  • Neon: Free projects with monthly CU-hours and storage per project.
  • Supabase: Two free projects, 500 MB, auto-pause.
  • MongoDB Atlas: Permanent M0 free cluster.
  • PlanetScale: No free production tier; ~$5 single-node Postgres entry (docs).
