Pick by task
  • One label per example / next token → cross-entropy
  • Many independent tags → BCE per tag
  • Skewed classes → class weights, focal, resampling
  • Real-valued target → MSE / MAE / Huber
  • Embeddings / retrieval → InfoNCE or triplet
  • Match a distribution → KL
  • Preference tuning → DPO; RL with reward → GRPO or PPO + KL (RLHF)
Cross-entropy (one correct class)
$$p_k = \frac{\exp(z_k)}{\sum_j \exp(z_j)} \qquad \text{(softmax)}$$
$$L = -\log p_y$$
  • $z_k$logit for class $k$
  • $p_y$probability on the true class

Reads as: only the true class appears in the loss — push its probability toward 1. PyTorch CrossEntropyLoss takes logits.

Binary cross-entropy
$$L = -\big[ y\log\sigma(z) + (1-y)\log(1-\sigma(z)) \big]$$
  • $y$label 0 or 1
  • $\sigma(z)$predicted prob. of class 1

Reads as: if y=1 only the first term survives; if y=0 only the second. Multi-label = one BCE per tag. Use BCEWithLogitsLoss.

Label smoothing
$$q_k = (1-\varepsilon)\,\mathbf{1}[k{=}y] + \frac{\varepsilon}{K}$$
$$L = -\sum_k q_k \log p_k$$
  • $\varepsilon$smoothing, e.g. $0.1$
  • $\mathbf{1}[k{=}y]$one-hot indicator
  • $q_k$soft target for class $k$

Example: $K{=}5$, $y{=}2$, $\varepsilon{=}0.1$ → $q = [0.02, 0.02, 0.92, 0.02, 0.02]$

Same CE, softer target: stops logits running to infinity (Szegedy et al.).

Focal loss
$$L = -\alpha (1-p_y)^{\gamma} \log p_y$$
  • $\gamma$focus on hard examples (often $2$)
  • $\alpha$optional class weight

Reads as: cross-entropy times a fade-out factor. Confident correct example (p_y≈1) → factor ≈ 0, barely trains. Lin et al., dense detection.

Hinge / margin
$$\text{binary:}\quad L = \max(0, 1 - y f(x)), \quad y \in \{-1,+1\}$$
$$\text{multi:}\quad L = \sum_{k \neq y} \max(0, 1 + z_k - z_y)$$
  • $f(x)$score (binary)
  • $z_y$logit of true class

Reads as: correct score must beat others by a margin of 1; once it does, zero loss. SVM heritage.

MSE (L2)
$$L = \frac{1}{n}\sum_i (y_i - \hat{y}_i)^2$$
  • $y_i$true value
  • $\hat{y}_i$prediction

Squaring makes big errors dominate (Gaussian-noise assumption). Diffusion trains MSE on predicted noise.

MAE (L1)
$$L = \frac{1}{n}\sum_i |y_i - \hat{y}_i|$$

Absolute distance — outliers count linearly, not quadratically. Predictions behave median-like; kink at 0.

Huber / smooth L1
$$e = y - \hat{y}$$
$$L = \begin{cases} \frac{1}{2}e^2 & |e| \le \delta \\ \delta(|e| - \frac{1}{2}\delta) & \text{else} \end{cases}$$
  • $\delta$knee between quadratic and linear

MSE-like near zero, MAE-like far out. Standard for bounding-box regression.

InfoNCE / NT-Xent (contrastive)
$$s(a,b) = \frac{a^\top b}{\|a\|\,\|b\|}$$
$$L = -\log \frac{\exp(s(q,k^+)/\tau)}{\sum_j \exp(s(q,k_j)/\tau)}$$
  • $q$query embedding
  • $k^+$positive match
  • $k_j$all keys in batch
  • $\tau$temperature

Reads as: softmax over similarities where the correct pair must win. No negatives → embeddings collapse (failure modes).

Triplet loss
$$L = \max(0,\; d(a,p) - d(a,n) + m)$$
  • $a,p,n$anchor, positive, negative
  • $d$distance; $m$margin

Reads as: penalty only while the negative is nearer than positive + margin. Hard-negative mining drives quality.

KL divergence
$$\mathrm{KL}(q \,\|\, p) = \sum_k q_k \log\frac{q_k}{p_k}$$
  • $q$reference / target
  • $p$model

Reads as: extra surprise if you use $p$ when truth is $q$. Not symmetric. Distillation, VAE, RLHF.

Dice / IoU (segmentation)
$$\mathrm{Dice} = \frac{2\sum_i p_i y_i}{\sum_i p_i + \sum_i y_i}, \quad L = 1 - \mathrm{Dice}$$
$$\mathrm{IoU} = \frac{|A \cap B|}{|A \cup B|}$$
  • $p_i$pred. mask prob.
  • $y_i$gt. mask 0/1

Optimizes overlap, so tiny foreground isn’t drowned by background. Often used as CE + Dice. Tversky adds FP/FN weighting.

Masked LM (BERT)
$$L = -\frac{1}{|M|}\sum_{i \in M} \log p(y_i \mid x_{\mathrm{masked}})$$
  • $M$masked token indices
  • $y_i$original token at $i$

Cross-entropy over the vocabulary, but only at masked slots. Wrong mask ratio → bad_mlm_mask.

Causal LM (GPT)
$$L = -\frac{1}{T}\sum_{t=1}^{T} \log p(y_t \mid y_{1:t-1})$$
  • $T$tokens predicted
  • $y_{1:t-1}$tokens before $t$

Per-token cross-entropy with a causal mask; labels shifted one step vs logits. Padding excluded via ignore_index.

Preferences & reinforcement learning
DPO (preference tuning)
$$\Delta(y) = \log \pi_\theta(y|x) - \log \pi_{\mathrm{ref}}(y|x)$$
$$L = -\log \sigma\big(\beta [\Delta(y_w) - \Delta(y_l)]\big)$$
  • $\pi_\theta$trainable policy
  • $\pi_{\mathrm{ref}}$frozen reference
  • $y_w$, $y_l$chosen / rejected
  • $\beta$preference strength

Reads as: raise the chosen answer’s log-prob relative to the rejected one, measured against the reference so the model can’t drift freely (Rafailov et al.).

PPO — clipped surrogate (RLHF workhorse)

Proximal Policy Optimization (PPO) updates a policy $\pi_\theta$ that generates text token by token. A reward model scores full responses $r(x,y)$. You do not backprop through the RM — sample completions, score them, then nudge $\pi_\theta$ to raise probability of high-reward strings. PPO limits how much the policy can change per step so training does not destabilize (Schulman et al.).

For one generated token (or a chunk), define the probability ratio vs the policy snapshot that collected the data:

$$\rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\mathrm{old}}}(a_t \mid s_t)}$$

$s_t$ is prompt plus tokens so far; $a_t$ is the token chosen. LLM code often sums log-probs over the response and uses one ratio per sequence — same idea. Advantage $A_t$ says whether this action beat expectation (from reward, RM score, or a critic / GAE).

$$L^{\mathrm{CLIP}} = -\mathbb{E}_t\Big[\min\big(\rho_t A_t,\; \mathrm{clip}(\rho_t,\, 1-\varepsilon,\, 1+\varepsilon)\, A_t\big)\Big]$$
  • $\varepsilon$clip range, e.g. $0.2$
  • $A_t$advantage (higher → increase $\rho_t$)

Reads as: if the update would push $\rho_t$ far from 1, the clip flattens the gradient — no huge policy jumps from one lucky batch.

Full RLHF loss (typical bundle):

$$L = L^{\mathrm{CLIP}} - c_{\mathrm{ent}}\, H(\pi_\theta) + c_{\mathrm{vf}}\, L^{\mathrm{value}} + \beta\,\mathrm{KL}(\pi_\theta \,\|\, \pi_{\mathrm{ref}})$$
  • $H(\pi_\theta)$policy entropy — bonus so outputs do not collapse (mode collapse)
  • $L^{\mathrm{value}}$critic MSE to returns (optional; some recipes drop critic)
  • $\pi_{\mathrm{ref}}$SFT checkpoint — KL keeps you near the starting model

What to log: metrics — reward, KL, clip fraction, entropy.

RLHF reward objective (what PPO optimizes)
$$\max \;\mathbb{E}[r(x,y)] - \beta\,\mathrm{KL}(\pi_\theta \,\|\, \pi_{\mathrm{ref}})$$
  • $r(x,y)$reward model score on completion $y$
  • $\beta$KL penalty weight (may appear inside $L$ above instead)

This is the goal; PPO is the optimizer used in classic RLHF (InstructGPT-style) because raw policy gradients are too noisy at LLM scale.

GRPO (group relative policy optimization)
$$r_i = r(x, y_i), \quad \bar{r} = \frac{1}{G}\sum_i r_i, \quad \sigma_r = \mathrm{std}(r_1,\ldots,r_G)$$
$$A_i = \frac{r_i - \bar{r}}{\sigma_r + \varepsilon}$$
$$L \approx -\frac{1}{G}\sum_i A_i \log \pi_\theta(y_i|x) + \beta\,\mathrm{KL}(\pi_\theta \,\|\, \pi_{\mathrm{ref}})$$
  • $G$completions per prompt
  • $A_i$group-relative advantage

Reads as: no separate critic network — compare rewards within the group, up-weight log-prob of better-than-average answers, down-weight worse ones, with a KL leash to the reference. Common in DeepSeek-R1–style reasoning RL; implementations often add PPO-style clipping on the policy ratio.

GAN adversarial loss
$$\min_G \max_D \; \mathbb{E}_{x}[\log D(x)] + \mathbb{E}_{z}[\log(1 - D(G(z)))]$$
  • $D$discriminator
  • $G$generator
  • $z$noise (not logits)

Two-player game. Known failure: mode collapse — G repeats a few outputs. WGAN / hinge / LSGAN change the scoring.

Add-ons (modify a loss)
  • Class weights — multiply each class’s CE term
  • Weight decay — shrink parameters in the optimizer (AdamW), not in the label loss
  • Mixup / CutMix — CE against blended soft targets
  • z-loss — small penalty on logit magnitude for LM pretrain stability
  • Entropy bonus — reward spread-out predictions in RL
Loss ≠ metric

Train CE, report macro-F1 under imbalance. Train MSE, report MAE for readable error. Low training loss can still mean bad calibration — check ECE on validation.
