How the LLM is wired into loops, tools, and state — “agent patterns” (also called architectures or orchestration styles). Model pick → LLM comparison. Memory → memory & state. Getting better over time → learning & improvement.

Agents — control patterns

Pattern vs model

The base LLM is one forward pass (maybe long CoT). An agent wraps it in a control loop: read state → call model → parse action → run tools → update state → repeat until stop. This page names common patterns for that loop — not specific products (LangChain, CrewAI, etc.), but the ideas they implement.

  • Tool — search, SQL, code runner, HTTP, MCP server — deterministic side effect + observation string.
  • State — messages, scratchpad, plan, retrieved docs (RAG is often one tool).
  • Policy — who decides the next action: model text, structured JSON, separate planner, or graph edges.
ReAct — reason + act interleaved
ReAct (Reason + Act)

The model emits a repeating trace: Thought (private reasoning), Action (tool name + args), then the harness injects Observation (tool output), then the model continues. No full plan upfront — the next step depends on what tools return.

  • Strengths — simple harness; easy to debug from logs; adapts when first tool call fails.
  • Weaknesses — many LLM calls; model may hallucinate tool args; long traces burn context.
  • Production note — same idea as native function / tool calling, but ReAct originally used free-form text parsing.
Other single-agent patterns
Function / tool calling (API-native)

Model returns structured JSON tool invocations (OpenAI-style, Anthropic tools, Gemini function declarations). Harness executes and appends tool results as special messages. Same loop as ReAct, but schema-constrained actions — less regex, better for production.

Plan-and-Execute

Planner LLM writes a multi-step plan (often bullet list); executor (same or smaller model) runs one step at a time with tools. Planner may replan after failures. Good when tasks decompose cleanly (travel, ETL); plan can go stale if world changes mid-run.

ReWOO (Reasoning WithOut Observation in loop)

Planner produces steps with placeholder variables for tool outputs; worker fills them in batch-style. Fewer round-trips than tight ReAct interleaving — trades flexibility for latency and cost.

Reflexion

After a failed episode (wrong answer, test failure), model writes a verbal critique stored in memory; next attempt conditions on that reflection. Outer loop over trials — not a different tool syntax, but a learning-from-mistakes pattern on top of ReAct or code agents.

CodeAct / code as action

Actions are Python (or shell) blocks in a sandbox; stdout/stderr become observation. One action can chain many ops (pandas, APIs). Common for data and SWE agents; security boundary is the sandbox (security).

Toolformer-style (training-time)

Model learns to insert API call tokens during pretraining/fine-tune so tool use is native in generation — pattern at training time; serve loop still looks like action → observation at inference.

Autonomous loop (AutoGPT-class)

Persistent goal in prompt + memory store + self-prompted subtasks until stop condition. High autonomy, high cost and drift risk — usually tightened in prod into bounded graphs or human checkpoints.

Search & multi-step reasoning
Tree / graph search (LATS, ToT-style)

Language Agent Tree Search and Tree of Thoughts expand multiple reasoning branches, score states, backtrack or beam-search. Many LLM calls; used when single CoT is unreliable (puzzles, planning). Often overkill for simple tool RAG.

Explicit state machine (LangGraph-style)

Nodes = functions or model calls; edges = conditional routing (human approval, tool success, budget). ReAct becomes one node; you add retries, fallbacks, and persistence explicitly — common for production agents.

Multi-agent patterns
Pattern Roles When it helps
Supervisor / router One model delegates to worker agents (research, code, writer) Clear sub-skills; isolate tool access per worker
Debate / critic Proposer vs reviewer rounds until consensus Quality on high-stakes drafts; expensive
Hierarchical crews Manager breaks goal; specialists execute Long projects with human-like division of labor
Handoff Sequential agents pass structured artifact Pipelines (extract → validate → publish)

Multi-agent is still mostly orchestration — each agent is usually ReAct or tool-calling under the hood.

Chooser
  • Default prod → schema tool calling + bounded graph (timeouts, max steps, allowlisted tools).
  • Research / ad hoc → ReAct text trace for readability.
  • Fixed playbook → plan-and-execute or ReWOO.
  • Code/data → CodeAct sandbox + Reflexion on test failures.
  • Need citations → RAG tool inside any pattern above — pattern does not replace retrieval.
  • Auth & tools → per-tool credentials, no prompt-only security (AuthN/AuthZ).
  • Persistent user/project context → context management + memory.
  • Improve from production runs → verifiers + logs first — learning & improvement.
