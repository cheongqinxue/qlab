DevOps — observability

Three pillars

Logs tell you what happened in discrete events (“payment failed for user 123”). Metrics are numbers over time (request rate, error rate, latency percentiles). Traces follow one request across services (API → DB → cache). You need all three for different questions; metrics alert, logs explain, traces locate bottlenecks.

What to instrument first
Golden signals (HTTP services)
  • Latency — p50/p95/p99 response time.
  • Traffic — requests per second.
  • Errors — 5xx rate, failed jobs.
  • Saturation — CPU, memory, queue depth, DB connections.
Logging hygiene

Use structured logs (JSON) with request id propagated across calls. Never log passwords, API keys, or full credit card numbers — see security logging rules. Log level INFO for normal path, ERROR with stack traces for failures; avoid DEBUG in prod unless sampled.

SLOs & alerting

An SLO (service level objective) is a target you agree on, such as “99.5% of requests complete under 500ms over 30 days.” An SLI is the measured indicator; an SLA is often a contract with customers. Alert on SLO burn (error budget draining fast), not on every blip — pages should be actionable.

Tools (roles)
Tool class Examples
Metrics Prometheus + Grafana, Datadog, Cloud Monitoring
Logs Loki, ELK, Cloud Logging, Datadog logs
Traces OpenTelemetry → Jaeger, Tempo, vendor APM
Errors Sentry (exceptions with context)
Uptime Synthetic checks (ping critical endpoints)

OpenTelemetry (OTel) is a common vendor-neutral way to emit traces and metrics from app code.

When things break

Start from the user symptom, check dashboards for correlated spike, open traces or logs for one failing request id, then recent deploys (CI/CD). Roll back if deploy time matches; otherwise fix forward with a tested patch. Write a short postmortem: timeline, root cause, action items — even for solo projects, future-you is the audience.

Chooser

Side project → platform logs + Sentry may be enough. Production API → metrics dashboard + alerts on 5xx and latency. ML API → add model version in logs and ML quality sampling on MLOps monitoring.
