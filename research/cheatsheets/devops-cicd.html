DevOps — CI/CD

CI vs CD

Continuous Integration (CI) runs on every push or pull request: install deps, lint, test, sometimes build an artifact. It answers “does this merge break the repo?” Continuous Delivery/Deployment (CD) takes a green build and promotes it to an environment — staging automatically, production with approval or fully automatic if you trust the gates.

Typical pipeline stages
  1. Checkout — clone git at commit sha (immutable reference).
  2. Test — unit tests, type check, lint; fail fast (testing, load smoke).
  3. Build — compile, bundle, or docker build (containers).
  4. Publish — push image or package to registry with tag = git sha.
  5. Deploy — update staging; smoke test; then prod or manual gate.

Keep prod deploys repeatable: the same pipeline definition, not a human running shell history on a bastion host.

Git workflow (broad audience)

Work on a branch; open a pull request (PR); CI must pass before merge to main. main stays deployable — if it is red, fixing it is priority one. Tag releases (v1.2.0) when you want a named rollback point; image tags often include git sha for traceability.

Tools you will meet
Tool Role
GitHub Actions CI/CD in repo YAML; common for OSS and small teams
GitLab CI Integrated pipeline + registry in GitLab
CircleCI / Buildkite Hosted runners, larger org patterns
Argo CD / Flux GitOps — cluster syncs to manifest repo (K8s)
Rollback & safety

Deployments should be rolling or blue-green so a bad version does not take everything down at once. Rollback means redeploying the previous known-good image tag, not rebuilding from memory. Database migrations need their own plan — app rollback does not undo schema changes automatically.

ML-specific CI (pointer)

Add smoke train and golden eval on PRs — details on MLOps pipelines. App CI still runs for the serving wrapper even when weights come from a registry.

Chooser

Personal project → GitHub Actions: test on PR, optional deploy to PaaS on main. Team → required reviews + staging deploy + smoke tests before prod. K8s shop → build in CI, deploy via GitOps or helm from same pipeline.
