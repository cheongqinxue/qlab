MLOps — registry & promotion

Why a registry exists

Training produces files; production needs a named, immutable release with metadata (who trained, on what data, with what score). A model registry stores those releases and tracks which stage they are in: development, staging, or production. Without it, “the model in S3” and “what users hit” diverge silently.

What to store per version
Artifacts
  • Weights (full checkpoint, LoRA adapter, or quantized bundle).
  • Tokenizer, config, custom code commit hash.
  • Eval report JSON and primary metric value.
  • For RAG: index build id, embedding model id, chunking version.
Metadata

Record training data snapshot id, hyperparameters, random seed, hardware, and pipeline run id. Link to W&B or MLflow run URL so debugging a prod incident starts from one id.

Promotion workflow
  1. Train completes and passes automated eval gates (pipeline).
  2. Register version as Staging — deploy to staging endpoint or shadow traffic.
  3. Human or policy check (security, legal, spot-check outputs) for high-risk domains (trust & policy).
  4. Promote to Production; keep previous prod version for instant rollback.

Promotion should be a state change in the registry, not an undocumented overwrite of model_latest.bin.

Packaging for serve
Containers

Ship a Docker (or similar) image with pinned Python/CUDA, inference server (vLLM, TGI, custom FastAPI), and an entrypoint that loads registry uri. Build the same image in CI that runs in prod so “works on my VM” matches Kubernetes or Cloud Run.

Quantization & format

Register the exact quant recipe (GPTQ vs AWQ, group size) with the artifact — serve runtimes reject mismatches (compression). Treat INT4 prod and FP16 staging as different registered variants if both exist.

Rollback

Keep at least one prior prod version hot-swappable. Rollback is re-pointing the deployment to the previous registry stage, not emergency retraining. After rollback, investigate via monitoring (monitoring).

Chooser

Solo project → git tag + W&B artifact may suffice. Team or compliance → MLflow Model Registry, W&B Registry, or cloud-native (Vertex Model Registry). Multi-component LLM+RAG → register a release manifest listing all artifact uris together.
