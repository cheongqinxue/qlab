Agents — grounding & hallucination

Issue vs tool

The issue is hallucination — confident claims not supported by allowed evidence: wrong facts, fake citations, invented tool arguments, or fluent answers when retrieval was empty. Grounding means tying statements to sources, tool JSON, or explicit uncertainty. Guardrails here are tools: citation checks, score thresholds, CoVe, schema validation — applied to this issue, not a separate product category. For a structured list of causes and how to diagnose which layer failed, see hallucination — causes & diagnosis; this page focuses on mitigations.

Failure modes (short)
Types of ungrounded output
  • Intrinsic — model fills gaps from priors.
  • Extrinsic — misreads or merges retrieved chunks.
  • Tool hallucination — wrong or nonexistent function calls (harness validation).
  • Empty-context answer — reply despite weak or empty RAG.
Symptoms in prod
  • Citation ids missing from index; quotes not substrings of source.
  • Numbers disagree with SQL/calculator tools.
  • Observation summaries that add facts (context shaping).
Mitigations (tools)
Retrieval & abstention
  • Score threshold — abstain when max similarity < τ.
  • Required citations — post-check chunk ids were in prompt.
  • Closed-book mode — “only use provided context.”
Verification loops
  • Chain-of-verification (CoVe) — verify then revise.
  • Self-consistency — sample multiple answers; disagree → escalate.
  • NLI / cross-encoder — entailment vs context for high-stakes sentences.
  • Tool-as-source-of-truth — figures from tool JSON, not prose.
Structured output

JSON with answer, citations[], confidence; harness validates before UI. Still verify citations.

Chooser
  • FAQ RAG → threshold + citations + quote substring check.
  • Analytics agent → numbers only from SQL tool output.
  • Creative tasks → relax grounding; policy still applies.
  • Regulated Q&A → CoVe + human queue on low confidence.
