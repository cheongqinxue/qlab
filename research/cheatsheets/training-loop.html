Training loop & schedules

The loop in one sentence

For each batch: forward → loss (loss) → backward → (clip grads) → optimizer step → log metrics (metrics). Everything else — schedule, accumulation, precision — wraps that core.

Epochs, steps & batch size
Epoch vs step
  • Epoch — one full pass over the training set. Fine for small data.
  • Step — one optimizer update (one or more forward-backward passes). LLM pretrain/SFT usually count steps or tokens seen, not epochs.
  • Schedulers and papers say “lr at 10k steps” — match that, not “epoch 3.”
Batch size & accumulation

Batch size — examples (or tokens) per forward pass. Larger batches → smoother gradients, more memory. Gradient accumulation — run $N$ small forwards with backward, accumulate grads, one optimizer step — simulates batch $N\times$ larger without fitting all samples in VRAM.

  • Effective batch = microbatch × accumulation × (number of GPUs in DDP).
  • Very large batch may need higher LR (linear scaling rule) — verify on val, not gospel.
Learning rate schedules
Warmup

LR ramps from 0 (or small) to base LR over first $W$ steps. Stabilizes early updates when activations and Adam moments are cold — especially transformers (no_warmup pathology in failure modes).

Common schedules
Schedule Shape Typical use
Constant Flat after warmup Short fine-tunes with early stopping
Step decay Drop LR at fixed milestones Vision classifiers, classic CV
Cosine decay Smooth curve to ~0 LLM pretrain, many HF recipes
Linear decay Line to end of training SFT when total steps fixed
One-cycle Up then down in one run Some fast fine-tunes (less common in huge LMs)

Optimizer details (AdamW, weight decay groups) → optimizers.

Discriminative LRs (fine-tune)

Lower LR on pretrained backbone, higher on new head — fixes layer_grad_imbalance. Parameter groups in PyTorch: optimizer = AdamW([{"params": head, "lr": 1e-3}, {"params": body, "lr": 1e-5}]).

Stability & precision
Mixed precision

FP16 or BF16 matmuls for speed; master weights often FP32. GradScaler scales loss before backward to avoid FP16 underflow — if loss goes NaN, scaler reduces scale. BF16 on supported GPUs (A100+) is simpler (wider exponent); still watch adam_collapse and loss spikes.

Gradient clipping

After loss.backward(), clip global grad norm to $\tau$ before optimizer.step(). Standard when training transformers or RNNs; pairs with warmup (explode).

Checkpointing & reproducibility
Checkpoints
  • Last — resume after crash.
  • Best val — early stopping selection; do not confuse with last.
  • Save optimizer state if resume must continue same Adam moments.
  • EMA (exponential moving average of weights) — optional shadow weights for eval; common in diffusion, sometimes LM.
Reproducibility
  • Fix seeds (Python, NumPy, torch, CUDA) for debug — full bitwise replay across GPUs is hard.
  • Log: git hash, data snapshot id, hyperparameters, library versions.
  • torch.backends.cudnn.deterministic — slower; use when chasing a bug.
Multi-GPU (sketch)

DDP (Distributed Data Parallel) — one process per GPU; each sees a different microbatch; grads all-reduced so every replica stays identical. Scale learning rate and batch with world size only when your recipe says so; always check val loss.

Inference scale → serving; not the same as training DDP.

Chooser
  • 7B SFT on 1 GPU → microbatch + accumulation, cosine or linear decay, warmup, AdamW, clip 1.0.
  • Small classifier → constant LR + early stop on val F1.
  • NaN at step 0 → warmup + clip before tuning schedule (failure modes).
  • Val weird but train fine → data splits, not cosine vs linear first.
