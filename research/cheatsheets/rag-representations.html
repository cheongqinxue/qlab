qlab cheatsheets

How embedding vectors are trained and scored. Search indexes → ANN sheet.

Representations & similarity

What you are learning when you “embed”

An embedding model maps text (or images) to vectors so that useful similarity in task space ≈ closeness in vector space. Training chooses that geometry via losses and pairs of examples. Retrieval then uses cosine similarity or dot product on those vectors (ANN sheet finds neighbors fast).

Bi-encoder (two-tower / Siamese)

Siamese usually means two inputs through the same (or tied) encoder; for retrieval, query and document each get one vector. Score = similarity(query_vec, doc_vec). Fast at scale — encode docs offline, encode query once per search.

Cross-encoder (not Siamese retrieval)

Concatenate query + passage → one transformer forward → relevance score. Accurate reranking; too slow to run on every doc in the corpus. Pattern: bi-encoder recall@50 → cross-encoder rerank to top‑5.

Cosine vs dot product
$$\cos(q,d)=\frac{q\cdot d}{\|q\|\,\|d\|},\quad q\cdot d=\sum_i q_i d_i$$
  • Cosine — direction only; invariant to vector length if models don’t normalize
  • Dot product — length matters; common when vectors are L2-normalized (then dot = cosine)
  • Training often normalizes or uses temperature-scaled dot products in contrastive loss
Training losses (contrastive family)
InfoNCE / softmax contrastive

For a query, one positive passage and many negatives: push similarity(pos) up, negatives down via softmax. In-batch negatives — other queries’ positives in the batch act as negatives (cheap, standard in dual-encoder training).

Triplet loss

Anchor (query), positive (relevant doc), negative (irrelevant): enforce sim(a,p) > sim(a,n) + margin. Older; InfoNCE-style often preferred at scale.

Multiple negatives ranking (MNRL)

Sentence-transformers style: one positive + many hard negatives per anchor with cross-entropy over scores — standard recipe for BGE, E5, domain retrievers.

ColBERT — late interaction
Not one vector per document

ColBERT keeps a vector per token for query and document. Score = sum over query tokens of max similarity to any document token (MaxSim). Finer than a single pooled embedding; index is larger.

ColBERTv2 + compression (residual PQ on token vectors) makes indexes more practical. Different from bi-encoder chunk pooling.

Matryoshka / “Russian doll” vectors (MRL)
Nested dimensions

Matryoshka Representation Learning (MRL) trains embeddings so the first $d$ dimensions are useful for many $d$ values (e.g. 64, 128, 256, 768). You can truncate at serving time for speed/memory with modest recall loss — same model, multiple operating points.

OpenAI text-embedding-3 “dimensions” parameter and similar APIs expose this idea; not every open model supports arbitrary truncation without MRL training.

Images & multimodal equivalents
CLIP-style (image ↔ text)

Two encoders (image CNN/ViT + text transformer); train on image–caption pairs with contrastive loss so matching pairs align in a shared space. Enables text→image search and zero-shot classification via prompt templates.

Image ↔ image
  • Same contrastive / Siamese idea on augmented views (self-supervised): SimCLR, MoCo, DINO
  • Supervised metric learning — triplet on class labels
  • Multimodal RAG: embed image patches or whole image; store alongside text chunks
Classic IR training pairs
  • DPR (dense passage retrieval) — separate question and passage encoders; contrastive with hard negatives
  • MSMARCO-style finetune on top of pretrained language models
  • Domain fit: continue training on your query–doc clicks or synthetic Q from docs
Chooser
  • Default production: strong bi-encoder (API or BGE/E5 class) + cosine on normalized vectors
  • Need max recall@k: add cross-encoder reranker or ColBERT-style index
  • Need cheaper storage/latency: MRL truncation or PQ/SQ compression (watch recall)
  • Images: CLIP or dedicated vision embedder; same ANN stack as text
