How embedding vectors are trained and scored. Search indexes → ANN sheet.

Representations & similarity

What you are learning when you “embed”

An embedding model maps text (or images) to vectors so that useful similarity in task space ≈ closeness in vector space. Training chooses that geometry via losses and pairs of examples. Retrieval then uses cosine similarity or dot product on those vectors (ANN sheet finds neighbors fast).

Bi-encoder (two-tower / Siamese)

Siamese usually means two inputs through the same (or tied) encoder; for retrieval, query and document each get one vector. Score = similarity(query_vec, doc_vec). Fast at scale — encode docs offline, encode query once per search.

Cross-encoder (not Siamese retrieval)

Concatenate query + passage → one transformer forward → relevance score. Accurate reranking; too slow to run on every doc in the corpus. Pattern: bi-encoder recall@50 → cross-encoder rerank to top‑5.

Cosine vs dot product
$$\cos(q,d)=\frac{q\cdot d}{\|q\|\,\|d\|},\quad q\cdot d=\sum_i q_i d_i$$
  • Cosine — direction only; invariant to vector length if models don’t normalize
  • Dot product — length matters; common when vectors are L2-normalized (then dot = cosine)
  • Training often normalizes or uses temperature-scaled dot products in contrastive loss
Training losses (contrastive family)
InfoNCE / softmax contrastive

For a query, one positive passage and many negatives: push similarity(pos) up, negatives down via softmax. In-batch negatives — other queries’ positives in the batch act as negatives (cheap, standard in dual-encoder training).

Triplet loss

Anchor (query), positive (relevant doc), negative (irrelevant): enforce sim(a,p) > sim(a,n) + margin. Older; InfoNCE-style often preferred at scale.

Multiple negatives ranking (MNRL)

Sentence-transformers style: one positive + many hard negatives per anchor with cross-entropy over scores — standard recipe for BGE, E5, domain retrievers.

ColBERT — late interaction
Not one vector per document

ColBERT keeps a vector per token for query and document. Score = sum over query tokens of max similarity to any document token (MaxSim). Finer than a single pooled embedding; index is larger.

ColBERTv2 + compression (residual PQ on token vectors) makes indexes more practical. Different from bi-encoder chunk pooling. ColBERT is retrieval scoring (late interaction), not the usual cross-encoder rerank step — see retrieval stages.

Matryoshka / “Russian doll” vectors (MRL)
Nested dimensions

Matryoshka Representation Learning (MRL) trains embeddings so the first $d$ dimensions are useful for many $d$ values (e.g. 64, 128, 256, 768). You can truncate at serving time for speed/memory with modest recall loss — same model, multiple operating points.

OpenAI text-embedding-3 “dimensions” parameter and similar APIs expose this idea; not every open model supports arbitrary truncation without MRL training.

Images & multimodal equivalents
CLIP-style (image ↔ text)

Two encoders (image CNN/ViT + text transformer); train on image–caption pairs with contrastive loss so matching pairs align in a shared space. Enables text→image search and zero-shot classification via prompt templates.

Image ↔ image
  • Same contrastive / Siamese idea on augmented views (self-supervised): SimCLR, MoCo, DINO
  • Supervised metric learning — triplet on class labels
  • Multimodal RAG: embed image patches or whole image; store alongside text chunks
EmbeddingGemma 2 — unified multimodal space

EmbeddingGemma 2 (Google; arXiv 2610.37364) is an open embedding model — not a chat LM — that maps text (incl. code), image, video, audio, and interleaved mixes into one shared vector space (768‑d by default). Same retrieval pattern as bi-encoders: encode items offline, encode query once, ANN search (indexes).

vs CLIP-style dual towers: modality encoders produce soft token sequences fed into a shared bidirectional transformer backbone (Gemma 4 lineage), then pool to one vector — not separate frozen image/text towers with contrastive pairing only.

  • Modular footprint — ~271M text-only · ~439M vision+text · ~577M audio+text · ~744M all modalities (load only encoders you need).
  • Training — multi-stage curriculum (text first, then multimodal); mix of distillation (Gemini Embedding 2 teacher), contrastive, and regularization objectives.
  • MRL — native truncation 128 / 256 / 512 / 768 dims (same idea as Matryoshka section above).
  • Task prefixes — short instruction strings steer the vector for search vs classification vs clustering (task-steered embeddings).
  • Deploy — 8k-token context; vision token budget tunable; QAT weight checkpoints for edge — ties to compression.

RAG angle: one embedder for “slide + caption + transcript snippet” in the same index if your pipeline normalizes on this model; cross-modal query (text question → video/audio/image docs) without swapping CLIP + text embedder. Still one vector per indexed unit unless you move to ColBERT-style late interaction.

Classic IR training pairs
  • DPR (dense passage retrieval) — separate question and passage encoders; contrastive with hard negatives
  • MSMARCO-style finetune on top of pretrained language models
  • Domain fit: continue training on your query–doc clicks or synthetic Q from docs
Domain adapt with little human labeling
Bottleneck mindset

Million hand-labeled query–passage pairs are unrealistic. Default playbook: generate or mine silver labels from your corpus, use automatic negatives (in-batch + retriever hard negatives), and keep a small human set (dozens, not thousands) as a regression gate. Human effort goes to spot-checking failure modes, not exhaustively annotating training data.

Order of operations
  1. Baseline — off-the-shelf embedder + chunking/index (chunking, ANN); fix hybrid BM25 and prefixes before training.
  2. Synthetic eval — hold out random chunks/docs; generate questions from them; positive = source chunk by construction (no human gold).
  3. Scale train pairs — same generators + filters; add mined hard negatives from the baseline retriever.
  4. Fine-tune — contrastive / MNRL for 1–3 epochs; prefer LoRA on embedder (PEFT).
  5. Re-embed corpus, rebuild index; compare on synthetic eval + tiny human slice + sampled RAG checks (systems).
Synthetic query–passage pairs (scale)
From each chunk (most common)
  • LLM prompt: “Write $n$ user questions this paragraph alone answers” — positive doc = that chunk (DPR-style synthetic data).
  • Vary prompts: FAQ style, keyword search, troubleshooting, “how do I …” — diversity beats one template.
  • Multi-question per chunk — multiplies pairs without new human input; cap per chunk to avoid near-duplicates.
Structure-aware silver labels (no LLM)
  • Title / heading → body — query = section title or first sentence; positive = chunk under that heading.
  • Key terms — TF-IDF or entity strings as pseudo-queries; positive = chunk containing them (noisy but free).
  • Parent doc — query from child chunk; positives = siblings in same section; negatives = random other sections (weak signal, cheap).
Cleaning synthetic data (quality > quantity)
  • Self-filter — drop Q if BM25 or baseline embedder does not rank source chunk in top‑$k$ (question not grounded).
  • LLM judge (batch) — “Is this question answered by the passage?” yes/no on a sample; tune filters, not full manual label.
  • Small cross-encoder — score (Q, chunk); discard bottom percentile pairs before training.
  • Deduplicate — near-duplicate questions and chunks (min-hash on text) so 100k pairs are not 100 copies.
  • Hold out docs — entire files excluded from train generators; use only for eval so leakage does not inflate metrics.
Negatives without labeling
Hard negatives (automatic)
  • In-batch negatives — other rows’ positives in the same training batch (free with InfoNCE/MNRL).
  • Retriever mine — for each synthetic query, top retrieved chunks except the source = hard negatives (refresh after each fine-tune round).
  • Same-doc wrong chunk — adjacent or sibling chunks as negatives (harder than random corpus draws).
  • No human “irrelevant” labels needed — only the positive is supervised (source chunk id).
Weak organic signal (when you have any)
  • Search logs, thumbs-up on answers, agent tool traces with chunk id — use as extra positives without building a full labeled set.
  • Session co-click: query text + opened doc chunk — silver pair; down-weight vs synthetic if noisy.
Measuring progress (minimal humans)
Mostly automatic metrics
  • Synthetic recall@k — on held-out chunks with generated Q; positive id known; track k you use in RAG (metrics).
  • Retrieval swap test — same index size; did fine-tuned model move source chunk rank up vs baseline?
  • Sampled RAG judge — LLM scores faithfulness on 20–50 real user queries (not full passage labeling).
Minimum human set

~20–50 queries you care about (real tickets or product questions), human picks acceptable chunk(s) once — regression only when you change embedder or filters. Not for training at scale; for catching jargon and policy failures synthetic pipelines miss.

When not to fine-tune
  • Wrong query: / passage: prefix, chunking, or missing hybrid — looks like “bad embeddings.”
  • Synthetic pipeline fails self-filter (source rarely in top‑k) — fix generation prompts or corpus parse first.
  • Corpus < few hundred chunks — prefer reranker only; contrastive overfits.
Fine-tune recipe (silver-label friendly)
  • Base: BGE / E5 / GTE / EmbeddingGemma — shared query/doc encoder; match production prefixes.
  • Loss: MNRL or InfoNCE + in-batch + mined negatives; 1–3 epochs, low LR ($10^{-5}$–$10^{-4}$).
  • LoRA first — enough for domain vocabulary; full fine-tune only if LoRA plateaus on synthetic eval.
  • Train on filtered synthetic; optionally mix small weight on organic silver pairs.
Ship checklist
  • Version embedder + filter recipe; full re-index after any embedder change.
  • Report: synthetic recall@k and small human regression set; sample RAG faithfulness.
  • Log prod queries + top chunk ids to feed the next hard-negative mine (still no manual labels).
Chooser
  • Default production: strong bi-encoder (API or BGE/E5 class) + cosine on normalized vectors
  • Domain gap: synthetic Q from chunks + mined negatives + LoRA → re-embed; ~50 human queries as regression gate only
  • Need better recall@k: ColBERT index/rescore (stage 1b) and/or cross-encoder rerank (stage 2) — when to stack
  • Need cheaper storage/latency: MRL truncation or PQ/SQ compression (watch recall)
  • Images / audio / video in one index: unified multimodal embedder (e.g. EmbeddingGemma 2) vs CLIP + text model pair
