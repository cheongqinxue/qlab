Information retrieval

What retrieval is

Information retrieval (IR) means: given a question, return the most relevant passages from a corpus. Retrieval-augmented generation (RAG) adds a step after that — a large language model (LLM) reads those passages and writes an answer grounded in them.

If retrieval picks wrong or empty chunks, the LLM will guess or hallucinate. RAG quality is mostly retrieval quality.

Lexical vs semantic search
  • Lexical — match words (BM25, TF-IDF). Strong on exact terms, SKUs, names; weak on paraphrase.
  • Semantic (dense) — embed query and documents into vectors; rank by cosine similarity. Strong on meaning; can miss rare tokens.
  • Hybrid — combine both lists (RRF is the usual merge; see fusion & ranking).
Embeddings

An embedding model maps text to a fixed-length vector so that similar meaning → nearby vectors. Same model must embed queries and documents at index and query time (or use a compatible pair).

  • Chunk text → vector → store in a vector index
  • Query → vector → nearest neighbors = candidate passages
Vector index (approximate nearest neighbor)

Exact brute-force compare against every vector is slow at scale. Indexes like HNSW or IVF trade a little recall for speed. Training and similarity: representations. HNSW, PQ, SQ, vendors: ANN sheet.

Metadata filters

Vectors alone ignore structure. Store metadata (tenant, date, product, ACL) and filter before or during search so users only retrieve documents they may read.

Retrieval stages — bi-encoder, ColBERT, cross-encoder
What “vector DB primary index” assumes

Most vector databases (and typical RAG tutorials) assume one dense vector per chunk from a bi-encoder (two-tower) model, then approximate nearest neighbor (ANN) search — see representations and ANN engines. They do not ship ColBERT as a default index type; ColBERT needs many vectors per document (per token) and MaxSim scoring, which is a different storage and query pattern.

Three scoring roles (often stacked)
Stage Mechanism Typical k Cost / latency
1 — First retrieval Bi-encoder + ANN (or BM25 hybrid) 50–200 Low; scales to huge corpora
1b — Stronger retrieval (optional) ColBERT index or rescore top‑N with MaxSim 100–1000 → 50 Medium; large token-level index
2 — Rerank (optional) Cross-encoder — one forward pass per (query, passage) pair 20–50 → 5–10 High per pair; only on small k

ColBERT is late interaction retrieval (token vectors + MaxSim), not the same as cross-encoder reranking. Production default: stage 1 only. Quality push: 1 → 2, or 1 → 1b → 2 when recall and precision both matter.

Cross-encoder reranking

Concatenate query and each candidate passage; a single transformer scores relevance. Too slow on the full corpus, so it runs after cheap first-stage retrieval. Improves order of the chunks the LLM actually sees.

ColBERT in production
  • Rescore — bi-encoder ANN returns top‑N; ColBERT MaxSim re-orders (no full ColBERT index on every doc)
  • ColBERT-as-retriever — dedicated index (RAGatouille, PyTerrier, Vespa-style tensors); rare as “primary” in managed vector SaaS
  • Multi-vector collections — some OSS DBs can store multiple vectors per point; you still own encoding and MaxSim logic
Metrics (offline)
  • Recall@k — was the gold passage in the top k results?
  • MRR / nDCG — ranking quality when multiple relevant docs exist
  • Hit rate — % queries with any score above a threshold

Golden sets, gates, faithfulness workflow → RAG evaluation. Formulas → metrics.

Lexical: BM25 (intuition)

BM25 ranks documents by term frequency in the doc, penalized by document length, with diminishing returns for repeated words. Inverted index = word → list of docs. No neural net; fast baseline and hybrid component.

When retrieval fails
  • Chunk too small/large — answer split across chunks
  • Stale index — product/docs changed after embed
  • Wrong language or domain in embedding model
  • No ACL on metadata — wrong tenant’s doc ranks high
