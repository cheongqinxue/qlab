qlab cheatsheets

Splits, leakage, and label quality — before you tune the loop (training loop). Metrics → metrics. Val gap → generalization.

Data for training

Data beats defaults

Most failed runs are bad splits, leakage, or labels — not the wrong Adam $\beta$. Fix the dataset story before chasing learning rates (schedules).

Splits
Train / validation / test
  • Train — fit weights.
  • Validation — pick hyperparameters, early stop, model selection (you will peek many times).
  • Test — touch once for final report; if you iterate on test, it becomes val.

For hyperparameter search, use train → val only; or train / val / holdout test frozen from day one.

Group splits (do not random-shuffle blindly)

If one user, document, or session contributes many rows, keep all rows in one split. Otherwise the model sees nearly duplicate content in train and val — metrics look great, prod fails.

  • Users → all rows of user A in train or val, not both.
  • RAG / search → same doc id or near-duplicate chunks grouped.
  • Time series → train on past, val on future (no future leakage).
Leakage checklist
  • Duplicate or near-duplicate examples across splits (hash text, MinHash).
  • Target encoded in features (predicting price when “list price” column remains).
  • Normalization stats computed on train+val together — fit scalers on train only, apply to val/test.
  • Test questions appearing in pretrain or RAG index built from “all data.”
Labels & noise
Label quality

Wrong labels teach the wrong thing; the model will fit noise if capacity allows. Spot-check a random batch; measure inter-annotator agreement on a slice; track label revision history.

  • Weak / silver labels — heuristics, model-generated, rules. Cheap scale; watch systematic bias.
  • Partial labels — multi-label missing tags treated as negatives hurts; use masked loss or explicit “unknown.”
Class imbalance

Rare positives dominate business value but not row count. Accuracy lies; use metrics from metrics (PR-AUC, F1 at chosen threshold).

  • Class weights in loss — up-weight rare class CE terms.
  • Resampling — oversample minority or undersample majority (watch overfitting repeats).
  • Focal loss — down-weight easy examples (loss functions).
Augmentation & mixing
Vision (typical)

Random crop, flip, color jitter, mixup/cutmix — synthetic diversity so the model cannot memorize pixels. Augment train only; val/test see clean preprocessing.

Text & LLM data
  • Paraphrase, back-translation — more phrasing variety for classifiers/embeddings.
  • SFT: quality of demonstrations beats raw count; dedupe near-identical instructions.
  • Do not augment eval sets to “improve scores.”
  • Embedding fine-tune: synthetic queries — representations (low human label).
Curriculum & mixture

Curriculum — train on easy examples first, then hard (or increasing sequence length). Mixture — sample batches from multiple sources (English + code + domain) with fixed ratios; change ratios when one skill lags.

Synthetic & scraped data

LLM-generated labels or distillation pairs scale fast. Risks: model copies its own errors, amplifies bias, and memorizes templated phrasing. Filter with rules, second model, or human spot-check; keep a human or gold eval set untouched by generation pipeline.

  • Pretrain web scrape → dedupe (MinHash), quality classifiers, PII/legal filters.
  • Agent trajectories for training → verifiers before FT (agents learning).
How much data?
  • Small task fine-tune — hundreds to thousands of good labels often enough with a strong base; thousands of noisy labels may hurt vs hundreds of clean.
  • Contrastive / retrieval — need hard negatives; volume without negatives gives false confidence.
  • LLM pretrain — Chinchilla-style: model size and token count should scale together; more tokens on a fixed small model helps up to a point (model lineage).
Chooser
  • Val great, prod bad → leakage or split groups first.
  • Rare class → weights + PR-AUC, not accuracy.
  • Domain shift → new data mixture, not only more epochs.
  • Embedding/RAG quality → data + negatives before bigger model.
